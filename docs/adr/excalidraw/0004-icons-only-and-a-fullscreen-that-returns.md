# 状态条只放图标（语言除外），全屏必须能退出

- 状态：已采纳（2026-11-04）
- 相关：[0001](0001-the-tab-runs-upstreams-web-build.md)、[0002](0002-bytes-move-through-the-host.md)

## 问题

标签页上方要有一条线告诉用户三件事：现在是什么状态、正在编辑哪个文件、什么时候保存过。
再加几个动作按钮，很容易变成第二条工具栏——而 Excalidraw 自己已经有一整套工具栏，两条并排
就是两个重心。

全屏是另一个坑：桌面宿主把插件 UI 挂在自己的 frame 里，那个 frame 不一定给了
`allow="fullscreen"`。`requestFullscreen()` 被拒绝时，按钮就成了死键：点下去没有任何反应，
用户以为插件坏了。

## 决定

**状态条 28 px，三个位置，没有文字按钮——语言切换是一个写着「中文/EN」的两字符按钮。**

| 位置 | 内容 |
| --- | --- |
| 左 | 状态点 + 状态词（准备中 / 就绪 / 失败），带 `title` 与 `aria-label` |
| 中 | 当前文件名，或待打开文件名，或无文件 |
| 右 | 语言、全屏、重载 |

语言按钮是这条规则里唯一的例外，并且只到“两个字母”为止：它必须自己说清切过去会变成什么语言，
一个图标做不到。它带的文字是**目标语言**（界面中文时显示 `EN`），`data-lang` 属性让测试能读到当前值。
点击走桥的 `craft:locale`，写的是应用自己的 `appLangCodeAtom`——不重载 iframe，不丢未保存的场景。

没有"在浏览器里打开"了：标签页**就是**编辑器，第二个窗口拿不到工作区绑定。
状态词走 locales（`tool.status`），不硬编码。

**全屏作用于标签页自己的容器元素，不作用于面板、也不作用于 iframe。** 这样退出按钮永远在
视野里。状态跟随 `fullscreenchange`，平台的 Esc 能把它恢复。

`requestFullscreen()` 被拒绝时（宿主 frame 没有 `allow="fullscreen"`，或策略拒绝），
壳自己铺满视口：同一个元素加 `fixed inset-0 z-[80] h-screen w-screen`，同一个按钮退出，
Esc 也退出。表现上一致，代码里只有一个 `overlay` 布尔。

## 为什么不是"把状态塞进 iframe"

iframe 里是上游应用，它有自己的 UI 语言（Excalidraw 的菜单、提示、快捷键）。把宿主的文件状态
画进去意味着往别人的 DOM 里插节点，上游一次改版就崩。状态条在外面，既是隔离，也是归属：
这一行是 Astravia 的话，不是 Excalidraw 的话。

## 代价

- 全屏走的是"元素铺满视口"和"真 Fullscreen API"两条路，两者在极端情况下观感略有差别
  （真全屏会隐藏系统 chrome）。刻意接受：能用真 API 就用，不能用也不能死。
- 图标按钮要靠 `title` / `aria-label` 才有语义，所以这两个属性是硬要求，不是装饰。
- 语言按钮破了“无文字”的原则。接受这个破例，但限定为两个字母，并且必须指向目标语言而不是当前语言。

## 不做的事

- 不加"打开浏览器"、"复制链接"这类标签页外的动作。
- 不把状态条做成可折叠或可隐藏——它只有 28 px。
- 不在 iframe 里注入宿主 UI。
