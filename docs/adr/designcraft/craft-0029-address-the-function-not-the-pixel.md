# craft-0029 — 按名字执行功能，而不是按像素

- **Status:** Accepted
- **Date:** 2026-11-09
- **Context:** craft 系列 0.0.27
- **Related:** [0024](craft-0024-the-agent-stays-in-the-frame.md) — 通道只剩像素、
  [0009](craft-0009-one-batch-and-a-text-map.md) — 一次批量与文字地图、
  [0017](craft-0017-the-selection-is-offered-through-the-apps-own-open.md) — 菜单助记符那一级

## The situation

到 0.0.26 为止，六个工具全部以**坐标**为语言：`act` 点一个位置，`probe` 读一片格子。
这对"把这一块调暗一点"是对的，对"导出 PNG"是错的——后者是一个有名字、有快捷键、有菜单行的命令，
模型却要先用 `probe` 找菜单位置、再算分数坐标、再赌一次点击。

结果就是用户看到的那种失败：**编辑器还是得人工操作**。功能明明存在，只是没有被当成功能来调用。

而像素通道本身还有一个上限：这条 wasm 画布没有命令总线（[0024](craft-0024-the-agent-stays-in-the-frame.md)），
没有可读的语义树，也就没有"按 id 调命令"这条路。可是编辑器自己实现了两层**名字**：菜单助记符
（`Alt` + 首字母，逐级往下）和快捷键。`open_document` 的最后一级已经证明了第一层可用。

## The decision

**加第七个工具 `menu`：按名字执行功能。**

```
menu { shortcut?: "ctrl+shift+s" }                  // 先试应用自己的绑定
menu { path: ["File","Export","Save for Web…"] }    // 再走菜单路径
menu { shortcut, path }                             // 两个都给：先快捷键，失败再走路径
```

- 一次按键就是一次 `craft:key`，没有时序问题；菜单路径是 `Alt`+首字母打开、逐字母下行、`Enter` 提交。
- 每一级之后都量一次画布，`attempts` 里能看到哪一步成了、哪一步没成；`invoked: false` 是"没跑起来"，
  不是崩溃，也不是静默成功。
- 名字从哪来：每个技能包里有一张 `references/commands.md`，由该应用自己的
  `references/upstream.md`（从上游 Rust 源码导出的命令表）生成。**path 一列可以直接照抄**。
- 表里某些行的显示名在上游导出时就已经残缺（`ZmIn`、`edit.redo` 这种），这些行**不生成 path**，
  只保留 id 与快捷键：给一个错的名字比不给更糟。

顺带做了同一件事的结构面：**一个工具一个文件**（`src/tools/<tool>.ts` + `shared/` + `index.ts`）。
七个工具此前挤在一个 700 行文件里，改一个参数要读完整张表；现在一条工具的参数、描述、返回
就在它自己的文件里，`tests/craft-tools.test.mjs` 会检查每个文件只注册一个工具。

## 三个地址，按代价排序

| 想做的事 | 用什么 | 代价 |
| --- | --- | --- |
| 有名字的功能（保存、导出、撤销、滤镜） | `menu` | 一次按键；失败可读 |
| 空间操作（拖一个渐变、调一个滑块） | `act` + `probe` | 一次批量 + 一次读数 |
| 需要看着调的判断（对齐、字距） | `probe` 的 `shot` + `Read` | 一张图 |

所以技能的开头写的是：**先找功能，再找像素**。这不是文风问题——先猜坐标再猜结果，正是"自动化不起来"的成因。

## What this does not do

- **它不假装能调任意命令 id。** 没有命令总线；`menu` 走的是界面，走不到的功能就是走不到，
  会在 `attempts` 里如实失败。
- **它不替代 `act`。** 画布中心的手势、拖动、画笔，仍然只有 `act` 能做。
- **它不保证助记符一定存在。** 有的菜单用首字母、有的没有助记符；失败信息里会指出是哪一段。
- **它不改编辑器。** 上游字节一个没动，`web/` 仍是发行包里那份。

## The cost

- 多一个工具名要进 prompt；换来的是一条捷径，省下一次 `probe` + 一次猜测点击。
- 命令表跟着 pin 一起过期：pin 升到新版本时，`commands.md` 要按新的 `upstream.md` 重新生成，
  技能里那句"表里没有的，以界面为准"就是为此留的余地。
