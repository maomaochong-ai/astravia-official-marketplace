# ADR 0012：工艺库随包——上游的 assets 移植为本插件的数据，不给模型整篇灌

- 状态：已接受（2026-10-29，随 0.0.1）
- 决策对象：`abilities/plugins/novelwright/agent/references`、`agent/styles`、`agent/voice.md`、`src/reference`
- 相关：ADR 0009（能力对齐）、ADR 0011（界面同构）

## 1. 背景

`ainovel-cli` 的写作水平不只来自提示词，还来自 `assets/` 里那批工艺文档：章节写法、钩子、对白、
情节结构、长篇规划、去 AI 味判据、质量清单，三套题材的弧线模板与风格样本，四套文风预设，以及一份
统一叙述声音的 `voice.md`。上游在拼提示词时把它们按需注入。

如果只搬代码不搬这批文档，插件的功能是「对等」了，**水平不对等**：同样一条路由，写手手里没有
关于前 20%、钩子密度、疲劳词的那套判据。

## 2. 决策

### 2.1 随包，作为插件自己的数据

复制进 `agent/references/**`、`agent/styles/**`、`agent/voice.md`，来源与许可写在
`agent/references/ATTRIBUTION.md`（上游 Apache-2.0）。此后**这三处就是本插件的规格**：
改法同改代码一样走评审，不再跟随上游漂移。

### 2.2 生成成纯数据，不做运行时文件 IO

`scripts/build-reference-library.mjs` 把 25 篇文档打成 `src/reference/library.generated.ts`
（`{ id, kind, title, body }[]`，约 3.1 万字符）。理由：插件的工具跑在主进程里，没有「读自己安装目录」
的稳定 API；把内容编进包，读起来是同步的、可测的、不会因为用户移动安装目录而失效。

- `npm run references` 重新生成，`npm run build` 前置执行；
- 生成文件**提交进仓库**，`tsc` 与 `vitest` 直接吃它，CI 不需要额外步骤；
- 守卫测试断言条目数（25）与四类 kind 都存在，忘了重跑生成会红。

### 2.3 用工具取，不整篇塞进提示词

上游靠注入，插件靠 `novelwright_reference`：不带 `id` 是目录（id / kind / 标题 / 一段摘要），
带 `id` 才返回正文，`budget` 按字符截断并标 `truncated`（截到行尾，不给半句话）。

这和 ADR 0007 的纪律一致：工具只返事实，读多少由当前动作决定。写手要写第 4 章时读 `hook-techniques`，
架构师规划悬疑弧时读 `suspense-arc-templates`，评审觉得「味儿不对」时读 `anti-ai-tone`——
而不是每次开新会话就灌 3 万字。

### 2.4 四类条目的分工

| kind | 内容 | 谁读 |
| --- | --- | --- |
| `guide` | 章节、钩子、对白、情节结构、长篇规划、去 AI 味、质量清单等 14 篇 | 写手 / 编辑 |
| `genre` | 悬疑 / 言情 / 奇幻的弧线模板与风格样本（6 篇） | 架构师 |
| `style` | 默认 / 悬疑 / 言情 / 奇幻四套文风预设 | 写手 / 编辑 |
| `voice` | 叙述声音的统一口径 | 全队 |

## 3. 被否决的方案

| 方案 | 否决理由 |
| --- | --- |
| 把 25 篇拼进 `agent/agents/*.md` 系统提示词 | 每轮都付费、且没人再看；上游是按需注入，不是全量灌注 |
| 声明成 `agent.skillPaths` 的 Skill | Skill 是给主对话智能体调用的能力，这些是写作工艺素材，不是可执行流程 |
| 运行时从安装目录读 Markdown | 插件没有稳定的自身路径 API；换个安装位置就静默读不到 |
| 只挑几篇「最有用的」搬 | 「功能对等」的要求是按能力面比，不是按我的口味挑 |

## 4. 后果

- 包体增加约 130 KB 源文档 + 74 KB 生成数据；在体积限制（单包 100 MB）内可忽略。
- 工艺文档与上游解耦后，上游改进不会自动进来；要跟进就重跑一次复制 + 生成，属于有意的显式动作。
- 工具面从 30 增至 31，`GATED_TOOL_IDS` 不变（这是读工具，不进门禁）。
