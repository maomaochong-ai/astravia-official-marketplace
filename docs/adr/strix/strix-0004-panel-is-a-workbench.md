# strix-0004 — 面板的形态：一张工作台，不是终端回放

- **Status:** Proposed
- **Date:** 2026-11-13
- **Context:** 插件 strix 0.5.6；上游 `strix/interface`（TUI + viewer 前端）
- **Related:** [0003](strix-0003-panel-reuses-host-and-subagents.md) — 面板只做展示与操作

## The situation

现在的面板是把上游 TUI「照抄进一个标签页」：

- 整块黑底 + 等宽字，右边一排带边框的圆角盒子（目标 0、智能体 0、计划 0、覆盖 0、笔记 0、问题 0）；
- 左侧是空的黑色区域，只在最上面飘两行 `preparing image` / `pulling image`；
- 底部一条极细的状态行写「扫描中 · 步 0」，和一个单行输入框。

三个具体问题：

1. **空态在指责用户。** 六个 `0` 并排出现，读者得到的信息是「什么都没有」，而不是「下一步做什么」。
2. **主区没有内容时没有形态。** TUI 里终端本身就是容器，空着也成立；标签页里空着就是一片黑，看不出是从属关系。
3. **终端仿真带来的副作用。** 深色主题下像工具，浅色主题下选中文字会看不见——`::selection` 用的是宿主默认，而文字颜色是插件自己写死的浅灰。

上游真正值得照搬的不是它的配色，而是它的**信息分组**：目标与模式 → 运行状态 → 实时轨迹 → 产出（findings / 覆盖 / 报告）。

## The decision

**面板做成一张工作台：顶部一条状态带，中间一条轨迹流，右侧一列可折叠的产出栏；空态写下一步，不写零。**

1. **顶部状态带**（常驻一行，不占大块高度）：目标数量、扫描模式、执行环境（docker / host）、当前模型、停止按钮。这些是「我现在在什么状态下」，必须一眼可见，而不是散在六个盒子里。

2. **中间轨迹流**：等宽字保留（工具输出本身是等宽的），但**行宽有上限**（约 110ch 居中），行距舒展，工具调用与回答用左侧色条区分，不再是一整片黑。空态是一句**怎么做**的话，不是「正在扫描…」。

3. **右侧产出栏**：目标 / 智能体 / 计划 / 覆盖 / 笔记 / 发现，各自一个**无边框分区**，标题右侧是计数与一句话摘要；有内容才展开，没内容的合并成一行「还没有记录」，点击才展开。计数为 0 时不摆一个 0。

4. **跟随宿主动效与主题**：
   - 背景、边框、次要文字改用宿主主题变量，保留一套终端强调色（绿 / 红 / 琥珀）作为工具语义，不整块黑；
   - `::selection` 显式声明（强调色底 + 深色字），浅色主题下选中不再消失；
   - 这是宿主里的一个标签页，不是终端窗口——不模拟终端边框与扫描线。

5. **启动状态只报一次，不留在日志里。** 「正在连接桥接服务」是一条**状态**，不是历史记录：连接期间显示在顶部状态带，成功后消失；失败时变成一条可读的错误（带原因），而不是留在轨迹里制造「僵尸正在连接」。

## What this does not do

- **不移植上游 viewer 的前端**（React 应用 + 自己的状态层），只照它的信息分组。
- **不再整块黑底**。终端的黑是工具的一部分（终端窗口本身），标签页不是终端窗口。
- **不引入图表库**：覆盖与计数用文字与条形，够读即可。

## The cost

- 与上游 TUI 的视觉相似度下降；换来的是在标签页里读得下去、在浅色主题下可用。
- 状态从「日志行」变成「状态字段」，需要 session 里有一处明确的 `boot` 状态，而不是靠往 log 里推两条字符串。
- 右侧改成分区后，全部展开时的信息量与现在相当，但默认更窄；用户点开才知道有什么——这是有意的取舍：统计不是内容。
