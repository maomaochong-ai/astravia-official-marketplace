# ADR 0021：面板没有输入框，只有配置与现场

- 状态：已采纳
- 日期：2026-11-15
- 关联：[ADR 0003](adr-0003-panel-reuses-host-session-and-model.md)（不造第二个 AI）、[ADR 0007](adr-0007-panel-is-a-dashboard.md)（不是第二份对话）、[ADR 0008](adr-0008-three-roles-of-the-panel.md)（三种职责）、[ADR 0013](adr-0013-environment-is-the-users-choice.md)（环境是用户的选择）、[ADR 0020](adr-0020-two-kinds-of-conversation-one-boundary.md)（两种会话一套边界）
- 取代：无

## 背景

用户提了三件互相关联的事：

1. **在宿主里说"测一下 staging.example.com"，面板的「目标」是空的。**
2. **对话流不该被原样搬进面板**，但也不该一句不留——要的是关键点：strix 工具调用链，加上对话里的重点。
3. **既然发消息是宿主的事，面板里的两个输入框就没有意义。** 首屏该做成配置页，工作台该专注现场。

三件的共同根因是同一件事：面板此前把自己当"半个对话客户端"——有输入框、有发送键、等着一句话把它激活；而它真正的价值（配置检测、工具链、台账、关键点）反而是次要的。

## 现场（读代码得到的事实）

| 现象 | 事实 |
|---|---|
| 目标为空 | 面板的 `targets` 只来自 `sandbox.targets`，即 `strix_sandbox_start` 的 `targets` 参数（`scan-screen.tsx:165`）。用户说的话、agent 声明过的 `strix_scope` 都不进面板；本机模式（`host`）下根本不建沙箱，于是永远是 0 |
| 对话流被搬或全丢 | `use-strix-session.ts` 对 `message-added` / `message-updated` 直接 `return`（1.0.7 的决定：不画正文）。用户看到的是"面板把这一轮丢了" |
| 输入框无意义 | 首屏 textarea + 「发送」→ `deliver()`（先 `sendPrompt`，失败才 `createSession`，再失败 `insertText`）；工作台 textarea + 「发送」→ 同一个 `deliver()`。两条路都只是把话交给宿主输入框，与用户自己在聊天框打字等价 |

`deliver()` 的 120 行是这套设计最贵的地方：它要处理"新会话页没有会话""拿不到 cwd""发送失败"三种情形，而它产出的效果与"用户直接在宿主输入框回车"完全相同。

## 决定

### 1. 面板不再有输入框

- **首屏 = 配置页**：模型 / 目录 / 执行环境（四态 + 检测动作）/ 团队 / 工具面 / 技能库 / 连接 / 运行日志 / 桥接状态，末尾一个「进入工作台」。没有 textarea、没有发送键。
- **工作台 = 现场**：状态带（首屏 / 新会话 / 停止）、运行记录、侧栏。底部不再有输入框，改为一行只读说明：话在宿主对话里说。
- 删掉 `start` / `send` / `deliver` 与其依赖（`sendPrompt`、`insertText`）、`useComposerHeight` 与拖拽手柄。保留 `newSession`（`createSession`）与 `stop`——它们不是"代发"，是面板自己的动作。

代价写在明处：面板不能替你发第一句话。收益是它不再假装自己是一个聊天框，也不会再把"拿不到工作目录"变成一条假报错。

### 2. 对话投影 = 关键点，不是正文，也不是空白

`domain/conversation-digest.ts`（纯函数，有测试）产出：

| 来源 | 产出 | 上限 |
|---|---|---|
| 用户这一轮说的话 | 一行诉求 | 96 字 |
| agent 的答复 | 只取"带结论的行"：标题、列表项、含主机/路径/命令/严重级/编号的行 | 6 行，每行 140 字 |
| 寒暄与过渡 | 丢掉（`好的`、`收到`、`sure`…） | — |

工具调用链不变：`strix_exec` 由服务画（有输出与退出码），其余 `strix_*` 由宿主事件画。摘要行与工具行同处一条时间线，读者能看出"说了什么"与"做了什么"的先后关系。

这不是把正文搬进来：面板里没有 markdown 渲染、没有复制按钮、没有第二个可滚正文。它在"一句不留"和"抄一遍"之间取的是**索引**。

### 3. 目标：候选与声明分开

- **声明**（权威）：`strix_scope` 的 entries 与 `strix_sandbox_start` 的 targets，来自服务。
- **候选**（提示）：`domain/target-extraction.ts` 从用户的话、agent 的答复、命令里认出的主机/URL/IP/CIDR，去重且排除本机与文件名。
- 面板两组都画，候选带 `从对话` 标签；已被声明覆盖的候选不重复出现（`newTargets`）。
- **候选不会自动写进范围**：声明范围是 agent 的动作（`strix_scope`），面板只读。误把"用户随口提到的域名"变成授权范围，比不显示更糟。

## 为什么不是别的形状

| 做法 | 为什么不 |
|---|---|
| 保留输入框，只是隐藏发送键 | 一个不能发的输入框比没有更让人困惑；而且它仍然要维护 `useComposerHeight`、拖拽、草稿状态 |
| 把宿主对话全文镜像进面板 | 两个可滚正文就是 0.7.1 删掉的那份冗余；宿主那边还有更好的 markdown 与回滚 |
| 只留工具链，对话一句不留 | 读者看不到"为什么打这个"，工具行变成没有主语的句子 |
| 候选自动并入 scope | 那等于让模型之外的解析器决定授权范围；误报一次就是越界 |
| 首屏去掉一切、直接进工作台 | 环境/模型/团队是"开始前必须看清"的事实，首屏是它们唯一的位置 |

## 代价

- **首屏少了一条"最直接"的入口**：以前按 Enter 就开跑。现在必须回到对话里说第一句。诚实地说，那本来就是宿主输入框的事。
- **摘要会漏**：一句话里没有信号词就没有点。宁可漏，也不把面板变成摘要器；漏了不影响证据，证据在工具行与台账里。
- **候选会认错**：`a.test` 这样的域名听起来就像主机。所以候选有标签、不参与授权，认错的代价是一行字。

## 验证

- `test/conversation-digest.test.ts`（11 项）、`test/target-extraction.test.ts`（13 项）——规则是数据。
- `test/panel-is-a-dashboard.test.tsx`、`test/scan-screen-truth.test.ts` 继续守"不抄正文"。
- 真浏览器量首屏与侧栏几何（`launch-centering` / 侧栏左边缘），确认去掉输入框后仍是同一套栅格。
- 真机：宿主里说一句带域名的话 → 面板目标区出现候选；agent 声明后候选消失、声明项出现。
