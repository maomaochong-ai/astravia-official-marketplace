# ADR 0023：首屏是"配置 + 说话 + 免责"，并且不再说谎

- 状态：已采纳
- 日期：2026-11-15
- 关联：[ADR 0022](adr-0022-composer-is-bidirectional.md)（对话框双向）、[ADR 0013](adr-0013-environment-is-the-users-choice.md)（环境是用户的选择）
- 取代：无

## 背景

1.2.1 上线后一轮集中反馈，六件事，其中两件不是"样式"，是**面板说了不真的话**：

1. 底部那条「ctrl+c 退出 · ● 桥接服务已就绪 v1.2.1」占一整行，信息只有两个字（就绪），
   却把首屏最底下的注意力吃掉了；它属于「连接」那一组事实。
2. **执行环境的「自动」在面板上永远显示成「本机」**：`envState` 只要看到
   preference 是 `auto` 就归到 host 分支，于是"有 docker 的机器上选了自动"也写着
   「在本机执行 · 无容器隔离」。服务侧其实是对的（`resolveEnvironment` 有 docker 就用容器），
   错的是面板把"用户选了自动"读成"我在本机跑"。
3. 输入框空着的时候是完全静的；而这一格最该说的是"可以直接说目标"。
4. 技能库 75 篇随包，但"没生效"的体感来自三处（下一节）。
5. 选了容器之后，没有任何地方能回答"容器应用装在哪、那 75 篇在哪个目录里"。
6. 大标题与副标题没有和对话框对齐；底部缺一段免责声明——这类工具会真的发起网络访问，
   说清楚是产品责任，不是免责套路。

## 决定

### 1. 删掉底部条，桥接状态并进「连接」

「连接」那一行本来就是回答"插件此刻通不通"：现在它是

```
连接      ● strix 40
          ● 桥接服务已就绪 · v1.2.3
```

两行同一列、同一条左边缘。`ctrl+c` 的键位提示不再单独占一行——它写在首屏的说明行里
（见第 4 条），按不按得动不靠一行小字提醒。

### 2. 「自动」必须说它这次会做什么

`envState` 改为**先解析、后命名**：拿服务探测到的 `mode` 与 `docker` 状态算出这次真实的落点，
再决定文案。三档，各自带上"自动"的限定词：

| preference | docker 状态 | 面板说 |
|---|---|---|
| auto | daemon 在 + 镜像在 | 自动 · 会跑在容器里 |
| auto | daemon 在 + 镜像不在 | 自动 · 镜像还没拉（给「拉取镜像」） |
| auto | daemon 不在 | 自动 · 没有容器，跑在本机 |
| host | 任意 | 在本机执行 · 无容器隔离 |
| docker | 三态同上 | 与现有一致（容器就绪 / 没有 docker / 镜像未拉） |

判据只读服务给的 `mode`/`docker.ready`/`imagePresent`，不再读 preference 字符串本身。

### 3. 输入框里逐字敲出的提示

`shared/components/use-typewriter.ts`：18ms/字、停 1.1s、9ms/字回删，三句循环，
两屏各一组范例（"测 staging.example.com 的登录" / "继续上一轮"）。
一旦有内容或只读就停；`prefers-reduced-motion: reduce` 下只显示第一句静态文本。

它是**占位符**，不是值：不写入草稿、不参与"能不能发"的判断。

### 4. 大标题居中、说明句删除

STRIX 的 ASCII 字与副标题改成与对话框同轴居中（`text-align: center` + 同宽列）。
删掉那一行"说一句就开始 · 文字交给宿主会话执行，回复以要点回到这里"——
它把两件事（怎么开始、回复去哪）说成了一句长话，而这两件事现在都有地方存在：
占位符逐字说完第一件，运行记录里的 `from` 分色说完第二件。

### 5. 技能库：三处修正

审计（`loadIndex` / `loadBodies` 实跑）发现，"不生效"不是没随包，是三处手感问题：

| 现象 | 根因 | 修法 |
|---|---|---|
| 让模型"load jwt" 得到 `missing` | 包名是 `authentication-jwt`，文件名是 `authentication_jwt`，按 `jwt` 查不到，且不告诉它接近什么 | `loadBodies` 支持 `-`/`_`/空格归一，并在 miss 时返回 `suggestions`（按名字与描述子串匹配） |
| 类别名当技能名传（`reconnaissance`） | 类别不是技能 | 同上：suggestions 里带上该类别的条目 |
| 模型不知道要先 list | 人设里只提了 `strix_load_skills` | `recon` / `exploit` 人设与团队工作流补上"先 `strix_list_skills`，再 load" |

### 6. 容器装在哪：一个新入口，只画真话

容器选中时首屏多一行「安装位置」，点开是一张两列对齐的表（标签左、路径右，路径 `nowrap` + 省略号）：

- **宿主路径**（docker 程序、docker 数据、镜像存储、随包工具链、台账目录、工作目录）：
  服务用 `fs.existsSync` 探过，存在 = 可点击在文件管理器里定位，不存在 = 灰掉并标明；
- **容器内路径**（`/usr/local/bin`、`/opt/strix`、`/workspace`）：**不可"打开"**——
  它不在宿主文件系统里。点击 = 复制一条 `docker exec … ls -ld` 命令，贴到终端就能看；
- **其它系统**（macOS / Linux / Windows 的默认位置）：标成参考，点击只复制。

判据在 `domain/install-paths.ts`（纯函数、6 项测试），存在性由 `/api/paths` 回答。

### 7. 底部免责声明

首屏最底下加一段小字（10.5px、`--sx-dim`、最大 72ch、上边框一道），内容是四句实话：
只用自有或书面授权的目标；工具会真实发起网络访问与命令执行；结果不构成合规或
漏洞已修复的证明；记录留在本机。**不放在弹窗里**——它要能被读到，也要能被忽略。

## 代价

- **首屏多两段文字**（安装位置表 + 免责声明）：矮面板下会挤；用 `max-height` + 折叠处理，
  默认不展开安装位置。
- **自动的三档文案比原来长**：状态位要能容纳"自动 · 没有容器，跑在本机"，窄屏下折行。
- **`/api/paths` 每次点开探一次 fs**：几个 `existsSync`，代价可忽略；但它不能证明
  "容器里那个目录一定存在"——所以容器条目只给命令，不给结论。

## 验证

- `test/install-paths.test.ts`（6 项）、`test/use-typewriter.test.ts`（5 项）、
  `test/env-auto-honesty.test.ts`（4 项）、`test/skills-loading.test.ts`（5 项）。
- 真浏览器：标题/副标题/对话框同一中心线；连接两行同一左边缘；安装位置表两列对齐、无换行。
- 真机：把 preference 设成 auto，在有 docker 的机器上确认面板写「自动 · 会跑在容器里」，
  并确认实际 `sandbox.mode === "docker"`。
