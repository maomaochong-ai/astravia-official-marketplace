# strix-0005 — 环境自备：工具链随包，装上就能用

- **Status:** Proposed
- **Date:** 2026-11-13
- **Context:** 插件 strix 0.5.8；用户反馈「装完还要自己准备环境」，宿主报
  `Stop the service before installing its runtime`
- **Related:** [0001](strix-0001-environment-without-docker.md) — 执行环境由宿主代备、
  Docker 降级为加速器；[0002](strix-0002-capability-parity-with-upstream.md) — host 模式
  的工具清单

## The situation

strix-0001 解决了「没有 Docker 也要能跑」，但只跑通了一半：`host` 模式用的是**用户机器上
已有的工具**。所以真实体验是：

1. 装完插件 → 启动 → 报「nmap / nuclei 未安装」；
2. 用户被要求去装 scoop / brew / go install —— 这正是 0001 想消灭的那件事；
3. 更糟的是，全新安装第一次启动还会直接失败：
   `Error: Stop the service before installing its runtime`。

第 3 条是纯实现缺陷：`boot()` 在服务可能仍处于运行/启动中时调 `install()`，而宿主明确拒绝
「运行中安装运行时」。它把一个「本来能自愈」的升级路径变成了硬错误，用户看到的是
「桥接服务不可用」——所以这个 ADR 先修顺序，再谈自备。

第 2 条是**定位错误**：0001 把「工具链」判给了用户的包管理器。工具链是插件能不能工作的
前提，不该是用户的前置作业。

## The decision

**工具链由插件随包携带、由宿主下载解包；用户什么都不用装。**

1. **工具链作为受管运行时制品（host-managed artifacts）。**
   与 `strix-bridge` 服务同一套机制：`plugin.json#providers.services[].runtime.platforms[tag]
   .artifacts` 声明每个平台的归档与 sha256，宿主下载、校验、解包到受管目录。区别只在于
   它是**工具集**而不是常驻进程。
   - 归档按平台发布（win32-x64 / darwin-arm64 / darwin-x64 / linux-x64 / linux-arm64）；
   - 校验不通过就不解包，报可读原因，不静默降级；
   - 不需要管理员权限：解包到插件自己的运行时目录，不写系统路径。

2. **`host` 模式的搜索路径 = 受管工具目录 + 用户 PATH。**
   插件把受管目录放在前面，于是「随包带的 nmap」优先于系统里可能存在的旧版；
   用户自己装过工具照旧可用。这条决定了「装完即用」是否成立。

3. **安装顺序固定为 stop → install → start，且每步幂等。**
   这是本次报错的直接修复：宿主拒绝运行中安装，所以先停；已停则跳过；安装失败只重试
   一次（同一份字节重复装没有意义），失败原因原样呈现给用户。

4. **包管理器提示降级为兜底。** `strix-0002` 里那份 `scoop/brew/pipx` 提示不再出现在
   主流程：只有随包归档在某个平台缺失时，才作为「这一平台暂时只能自己装」的说明出现。

5. **首次使用是异步准备，不是阻塞。** 下载与解包在后台进行，面板顶部一条进度
   （字节数/百分比 + 取消），准备完成前「开始扫描」保持禁用并说明原因；不出现
   「正在连接…」这类看不出进度的字样。

## Considered options

- **继续要求用户装工具（现状）**：实现成本为零，但把插件的可用性绑在用户的包管理器上，
  且不同平台还要分别教。**否。**
- **插件自己用包管理器静默安装**：要管理员权限、会改系统状态、失败无法回滚。**否。**
- **插件用自己的下载器（不走宿主 artifacts）**：绕过宿主的 sha256 校验与代理策略，
  在受限网络下更差，还要自己维护断点续传。**否。**
- **只支持 Docker（回到上游形态）**：见 0001，Docker 仍然是可选加速器。**否。**

## What this does not do

- **不承诺所有工具都能随包分发。** 有许可限制或需要动态库的工具必须由用户提供；这类工具
  在面板里逐项标注「需自行提供」，并且**在计划阶段就说明**，而不是扫到一半才失败。
- **不代装 Docker / 不开虚拟化**（0001 的结论继续有效）。
- **不在安装期间假装可用**：准备没完成时扫描按钮禁用，并写明还差什么。

## The cost

- 每个平台的归档与 sha256 要随版本维护；发版体积变大，CI 需要产出多平台制品。
- 「受管目录优先于 PATH」意味着用户系统里的同名工具可能不生效——必须在面板里显示实际
  使用的是哪一个（路径与版本），否则排查会变成猜。
- 首次使用多一次下载等待；换来的是用户不需要知道自己装了没有。
