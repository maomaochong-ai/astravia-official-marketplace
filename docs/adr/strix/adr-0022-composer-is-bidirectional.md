# ADR 0022：对话框回来，双向但不造第二个 AI

- 状态：已采纳
- 日期：2026-11-15
- 关联：[ADR 0003](adr-0003-panel-reuses-host-session-and-model.md)（不造第二个 AI）、[ADR 0007](adr-0007-panel-is-a-dashboard.md)（面板不是第二份对话）、[ADR 0020](adr-0020-two-kinds-of-conversation-one-boundary.md)（两种会话一套边界）
- 取代：[ADR 0021](adr-0021-no-composer-config-and-live-view.md) 的"面板没有输入框"

## 背景

1.1.0 把面板里的两个输入框删了，理由写得很硬：面板发出去的话，效果与"用户在宿主输入框回车"完全相同，而那 120 行投递逻辑只是把同一件事做三遍。

删掉之后暴露的是另一半：

- 看着现场想补一句（"继续""换成 443""这条先别打了"），必须切回聊天区、找对会话、再切回来。**两屏之间的往返成本被转嫁给用户**；
- 首屏于是只剩"读"，没有任何"说"的入口——一个只能读的配置页，用户在会话里跑评估时根本不会打开它。

所以用户的原话是"还是加上对话框吧，对话框能够和宿主双向交互"。这一版按那句原话来：**加回来，但只做入口，不做第二个 AI，也不做第二份对话。**

## 决定

### 1. 一个对话框，两个屏共用

`shared/components/panel-composer.tsx`：`> ` 提示符 + 文本行 + 底条（左键位、右「发送」）。首屏的底条多一颗「工作台」，工作台的多一颗「新会话」。Enter 发送、Shift+Enter 换行、输入法组合中不拦、最多六行——与宿主聊天框一致。

两屏各存自己的草稿：离开首屏再回来，没发出去的话还在；它不与宿主的输入草稿抢同一个 atom。

### 2. 方向一（面板 → 宿主）：只走宿主那条路

顺序与 1.0.4 一致，三道：

1. **先 `sendPrompt`**——新会话页也能发，宿主按当前目录自己建会话；
2. 失败才 `createSession(cwd)`（cwd 依次取：当前会话 → 宿主打开的目录）；
3. 再失败就把话放进宿主输入框（`insertText`），并如实说"按 Enter 就开始"。

三道全失败才报"没能把指令交给宿主对话"。**插件侧零模型调用**，也没有第二份 messages。

### 3. 方向二（宿主 → 面板）：只要点，不要正文

宿主的回复进面板时经过 `domain/conversation-digest.ts`：

| 来源 | 面板里留下什么 |
|---|---|
| 用户这一轮说的话 | 一行诉求（`from: "you"`，≤96 字） |
| agent 的答复 | 只取带结论的行（`from: "agent"`，≤6 行、每行 ≤140 字） |
| 流式增量 | 不留（每一帧推一行等于抄正文） |
| 寒暄与过渡 | 丢弃 |

两个方向在轨迹里靠 `data-from` 分色：左边一条竖线，用户那句亮一档。读者不该靠文风猜谁说的。

### 4. 团队会话仍然只读

宿主的 `sendPrompt` 在团队会话里打的是**上一个单会话**（`pluginSendMessageRef` 不跟着团队切换），插件侧没有正确的落点。所以那里输入框不可写，底条写一句为什么，而不是留一个按了没反应的键。

## 为什么这次不算"又走回去"

| 1.1.0 的顾虑 | 这一版怎么处理 |
|---|---|
| 投递逻辑是"同一件事做三遍" | 那三遍是宿主自己给的三个入口，缺一个就有一种场景发不出去（新会话页 / 拿不到 cwd / 会话没起来）。它们全部指向宿主，不是三份实现 |
| 面板会变成第二份对话 | 仍然只有摘要：没有 markdown 渲染、没有复制按钮、没有第二个可滚正文 |
| 会出现第二套 AI | 没有：`ctx.ai` 零调用，权限表无 `ai.*`，`test/panel-composer-bidirectional.test.ts` 扫代码 |
| 首屏会变成聊天页 | 首屏仍是配置页：对话框在上面，事实表在下面，两者同一条右边缘（72ch） |

## 代价

- **多一个要维护的控件**：Enter/Shift+Enter/输入法/行高上限各一条，`test/panel-composer-bidirectional.test.ts` 守着。
- **两个草稿**（宿主一个、面板一个）：切回聊天区时，面板里那半句话还在，容易以为已经发出去。这是"两处都能输入"的固有代价；面板在发送成功后会清空，未发送时也不写进宿主的 atom。
- **团队会话的输入框看起来能用**：所以它被画成虚线并给一句说明，而不是隐藏——隐藏会让用户以为"这个面板没有输入能力"。

## 验证

- `test/panel-composer-bidirectional.test.ts`（11 项）：两屏挂同一个组件、三道次序、`ctx.ai` 零调用、团队只读、双向摘要、Enter/Shift+Enter、六行上限、空白禁用。
- 真浏览器四档宽（1180/760/430/360）：对话框与事实行左右边缘一致（548/548、382/382、312/312），发送键与「工作台」同高 24px，底条零溢出，两个方向的左边框颜色不同。
- 真机：首屏写一句 → 宿主会话收到并开始执行 → 面板离开首屏 → 回复以要点出现 → 在面板里补一句"继续"能送到同一个会话。
