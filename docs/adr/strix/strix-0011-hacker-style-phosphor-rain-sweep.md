# strix-0011 — 黑客风的具体形态：磷光、数据流、行首扫光

- **Status:** Accepted
- **Date:** 2026-11-14
- **Context:** 用户要求「整个插件界面更黑客风，首屏有黑客风动画」，并选择由他挑方向、我实现
- **Related:** [0004](strix-0004-panel-is-a-workbench.md)（工作台）、[0009](strix-0009-tui-as-the-interface-baseline.md)（以上游 TUI 为基线）

## The decision（四个选项，用户已选）

| 项 | 候选 | **选定** | 落点 |
|---|---|---|---|
| 首屏动画 | 开机序列 / 扫描线噪点 / 打字机 / **数据流** | 数据流背景 | `launch-screen.tsx` 的 `RAIN_COLUMNS` + `.astra-strix-rain` |
| 强度 | 克制终端感 / 明显终端风 / **全绿磷光** | 全绿磷光 | `.astra-strix-term.astra-strix-phosphor` 变量覆盖 + 扫描线 |
| 工作单元 | 只列沙箱会话 / 也显示宿主子智能体 | 只列沙箱会话 | ADR 0010 原样 |
| 扫光位置 | 只状态带 / **状态带 + 轨迹行首** / 状态带 + 首屏 | 状态带 + 行首 | `.astra-strix-sweep`（6 格）+ `[data-size="row"]`（4 格） |

## Why these and not the others

**数据流而不是打字机**：打字机的信息在 wordmark 里已经存在（它就是几行 ASCII），再逐字打一遍是
把同一件事做两次；数据流是**背景**，不占阅读节奏，且能与任何内容共存。

**磷光而不是「明显终端风」**：用户要的是"黑客风"，而中间那档（加深对比 + 等宽化）在暗色下与
磷光差别很小，在亮色下又多出一堆灰阶需要维护。磷光只有一个决定：单色绿 + 两个例外色，规则简单
到不会被后续改动破坏。

**为什么红与琥珀留着**：单色到底会让「失败」和「成功」只差一个字形。用户的原话是"红/琥珀只留给
失败与进行中"，所以 `--sx-red` 只用在 `data-state="fail"`、`--sx-amber` 只用在 running/警告。

**行首 4 格而不是 6 格**：一行的动静必须比标题栏小一档，否则一屏十个 running 行会一起闪。

## 实现要点（三条都可被测试钉住）

1. **磷光是变量覆盖，不是硬编码黑底**：
   `.astra-strix-term.astra-strix-phosphor` 覆盖 `--sx-*`，背景仍是
   `color-mix(in srgb, #04120a 92%, var(--background))`——宿主亮色主题下不会把面板钉成纯黑
   （ADR 0004 的教训：整屏黑在亮色主题里让选中文本变成空白块）。
2. **数据流是纯 CSS 且固定字符集**：首屏 46 列 / 工作台 58 列，每列 18–52 字，
   字符按 `hash(column,row)` 取（xorshift32），不用 `Math.random()`——截图与测试可复现；
   `prefers-reduced-motion` 下静止。
   **逐列随机是 1.0.7 的修正**：1.0.2 用 `(column*7 + row*3) % len` 取字符、`nth-child(2n/3n/5n)`
   给速度，字符落在等差斜线上、速度只有四档，屏幕上就是一道道平行斜纹加周期性横波——
   用户的原话是“有规则的竖向流动，希望无规则”。现在速度（7–31s）、相位（负延迟 0–40s）、
   长度、亮度、断行位置（约 1/8 空格）五个维度各自抗动，仍保持确定性。
3. **扫光用 keyframes 不用 JS 计时器**：上游是 Go 每帧算一遍 palette（`view.go:962`），
   浏览器里用 9 档亮度的 keyframes 等效，且不与滚动/resize 抢帧；`data-active="no"` 时静止。

## What this does not do

- 不做开机序列动画：它要跑真实探测（docker/skills），而首屏已经在用 `boot` 行显示真实状态，
  动画版会把"真实"换成"演出"。
- 不做全屏 CRT 弯曲/闪烁：可读性代价太大，且与宿主的滚动容器冲突。
- 不把磷光做成主题设置项：一个插件不需要第二套主题系统；宿主换主题时变量仍被覆盖。

## The cost

- 磷光在**亮色主题**下对比度偏弱（绿字压在浅底上）。缓解：背景 `color-mix` 会跟宿主的
  `--background` 混，暗色下才真的"磷光"；亮色下退化成浅绿卡片，可读但不惊艳。
- 数据流在很窄的面板里会挤（18 列固定）。已由 `.astra-strix-rain` 的 `overflow: hidden` 裁掉多余列，
  代价是窄屏下只剩几列。
