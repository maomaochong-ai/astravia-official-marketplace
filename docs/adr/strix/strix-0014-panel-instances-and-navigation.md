# strix-0014 — 面板实例、首屏/工作台切换，以及"多开"能做到哪一步

- **Status:** Accepted
- **Date:** 2026-11-14
- **Context:** 插件 strix 0.9.1；用户要求「插件工作台无法在首屏和工作空间界面切换」「希望有多开：首个对应当前项目下首个会话，新开的可以在插件侧发消息时在当前项目下新开会话」
- **Related:** [0007](strix-0007-panel-is-a-dashboard.md)（面板是仪表盘）、[0008](strix-0008-three-roles-of-the-panel.md)（三种职责）

## 两个请求，两种可行性

**请求 A：首屏 ↔ 工作台切换。** 完全可做，而且是必须修的——之前屏幕由"服务里有没有评估"决定
（`hasAssessment`），用户一旦开始扫描就**回不去**首屏看配置，只能看工作台。

**请求 B：多开。** 需要先分清"多开"的三种意思：

| 想要的东西 | 宿主当前能不能 | 结论 |
|---|---|---|
| 同一个标签页里放多个面板（并排） | 不能：`registerActivityTab` 一个 id 一个组件，宿主自己管理挂载 | 做不到 |
| 再开一个 Strix 标签页 | 不能：宿主按 plugin id + tab id 去重 | 做不到 |
| **一个面板，但能换绑哪个会话** | 能：`ctx.conversation.createSession(cwd)` 会让新会话变成活跃会话，面板本来就跟随活跃会话 | **这一条能做，也是唯一诚实的做法** |

所以"多开"在这里落地为：**面板跟着"当前活跃会话"走；用户可以在当前项目下新开一个会话，
面板随即跟过去**。这正好对应用户描述的"首个开的界面对应当前项目下的首个会话；新开的在插件侧
发消息时在当前项目下新开会话"——只是"新开"由显式的「新会话」按钮触发，而不是发消息时隐式建。

为什么不做隐式建会话：发消息时突然多出一个会话，会让"我刚才在哪个会话里"变得不可回答；
而且 `createSession` 默认 `navigate: true`，会改变宿主路由——这种副作用必须由用户点出来。

## The decision

1. **两屏可切**：工作台状态带加「首屏」按钮；点它 `launchPinned = true`，此后**不再**被
   "宿主流一转就跳工作台"自动拽走（自动化只在从未手动干预时生效）。首屏的 `onQuit` 仍然是
   `ctrl+shift+c`。
2. **「新会话」按钮**：在当前 `cwd` 建会话（`createSession(cwd)`），面板跟随新的活跃会话；
   没有 cwd 时如实报 `log.noWorkspace`，不猜目录。
3. **面板与会话的绑定沿用 0.6.0 的 `session-store`**：按 conversationId 存快照，
   切回旧会话时水合而不是从零开始。多会话共享一个沙箱与一份台账（服务侧按 sessionId 分文件）。

## 为什么不做"面板内多实例"

宿主的 `registerActivityTab` 只接受一个 `component`，标签页头由宿主渲染，插件无法在同一个标签里
再分出一个可拖拽的窗格。硬做的形态（自制分栏 + 自管分隔条）会让"哪个面板对应哪个会话"分裂成两套
状态，正是 0007 已经清掉的那类冗余。

## What this does not do

- 不做标签页复制：宿主不支持，插件也不该绕过。
- 不做"每个会话一个沙箱"：沙箱是 run 级，不是 session 级（ADR 0002）。
- 不在发消息时隐式建会话（理由见上）。

## The cost

- 「新会话」会让宿主跳到新会话（`navigate` 默认行为），旧会话的扫描仍在后台跑——面板此时显示的是
  新会话的现场，旧会话的进度要去宿主会话列表里看。这一点写进按钮的 title，不靠用户猜。
- 首屏被"钉住"后，需要用户自己点回工作台（或用胶囊再触发一次）。这是刻意的：自动化不该覆盖
  用户显式的意图。
