# strix-0008 — 面板的三种职责，与「可检查」的硬要求

- **Status:** Accepted
- **Date:** 2026-11-14
- **Context:** 插件 strix 0.7.2；用户看图后问「计划 / 覆盖 / 笔记这三个功能上游是否存在、是否死功能」
- **Related:** [0007](strix-0007-panel-is-a-dashboard.md)（面板是仪表盘，不是第二份对话）

## The situation

0007 把面板从"复述对话"里摘出来，剩下的空间该由什么填满？截图里的三个盒子（计划、覆盖、笔记）
给出了答案的一半：它们是**只有面板能显示**的东西。但它们当时只列标题：

| 面板 | 上游有吗 | 上游怎么实现 | 0.7.1 的状态 | 真实问题 |
|---|---|---|---|---|
| 计划 | 有（`tools/todo/tools.py`） | `create_todo` / `update_todo` / `mark_todo_done` / `mark_todo_pending` / `delete_todo`，按 status+priority 排序，落 `todos.json` | write/update/list 有，**删不了** | 计划变化时只能把作废项标成 done——等于谎称做完了 |
| 覆盖 | 有（`tools/coverage/tools.py`） | `record_coverage` / `update_coverage` / `list_coverage`，带 outcome 计数与 provenance | record/list 有，**改不了** | 先把面记成 clean，后来确认越权，只能再记一条相反的，台账自相矛盾 |
| 笔记 | 有（`tools/notes/tools.py`） | CRUD + 六个分类 + 列表给 preview | CRUD 齐全 | **面板只画 id 与标题**，正文打不开——写了也看不见，这才是"死功能"的感觉 |

所以"死功能"不是没有工具，而是三处具体的断点：**删不了、改不了、读不了**。

## The decision

面板有三种职责，一种都不能省，而且各有硬要求：

| 职责 | 内容 | 硬要求 |
|---|---|---|
| **证据** | 命令、退出码、耗时、输出尾巴、会话 | 永远停在最新一行；读者往上滚时不抢回（0007 的续条） |
| **台账** | 计划、覆盖、笔记、发现、威胁模型、MCP 连接 | **每一行必须可检查**：要么能展开看正文，要么标题上写明"还有 N 行" |
| **控制** | 停止、会话（background/kill）、范围、发布报告 | 只在真能生效时可点，不允许"看起来能点" |

并把"写"和"读"分开：

- **写归 agent**（它有工具）：面板不提供"帮我加一条计划"——那会变成第二个决定计划的地方。
- **读归操作者**（他在面板前）：所以面板必须能读到正文，而不只是标题。
- **导航归对话**：要回溯说过什么，去聊天区（0007）。

三条补口，各对应上面的断点：

1. `strix_todo_remove`（上游 `delete_todo`）：作废项删掉，而不是假装做完。
2. `strix_coverage_update`（上游 `update_coverage`）：就地改正，并留 `updated_at`，报告里能看出
   哪些结论被修正过。
3. 笔记面板可展开：点一行才 `strix_note_get`；折叠时显示服务给的 120 字 `preview`
   （`notes.list` 本来就截断好了，不传全文——正文可能含 token）。

## The scroll rule（同一次决定的副产品）

「流式输出时滚动条往上走」不是渲染 bug，是滚动容器的语义：`scrollTop` 从顶部量，内容向下增长时
它不变，视口于是相对内容上移，新行落在视野外。

规则取聊天界面的通行做法，写进 `scroll-stick.ts`（纯函数）与 `use-stick-to-bottom.ts`（DOM）：

- 贴底（距离 ≤ 24px，容忍亚像素与布局取整）→ 跟着新内容走；
- 读者自己往上滚了 → 不抢回来，显示 `N 条新消息 ↓`，点了才回底；
- 面板变高（窗口缩放、右栏收起）也贴底，但只在跟随状态下。

## Considered options

- **面板做成纯只读快照**（定时 refresh，不跟随）：简单，但运行中看不到进度，等于把"实时"让给
  了对话的工具卡片——那正是 0007 要去掉的重复。**否。**
- **让面板自己也能写台账**（加"新建笔记"按钮）：界面完整，但两个地方决定计划与覆盖，冲突时谁
  优先没有答案。**否**——读与写分家。
- **滚动时永远强制到底**：最简单，但读者一旦想自查上一条命令就被拽回去。**否。**

## What this does not do

- 不给计划/覆盖加"编辑"控件：读与写分家（见上）。
- 不在 `/api/state` 里传笔记正文：只传 preview。正文按需取，因为它可能含凭据。
- 不把"还有 N 行"做成翻页：面板不是表格应用，缩小过滤面由 agent 决定（`strix_coverage_list`
  支持 outcome 过滤）。

## The cost

- 三个工具的签名与上游不完全一样（`strix_` 前缀 + 单条 update 语义），照抄名字没有价值，行为
  一致才有（ADR 0006 的规则）。
- 面板点多一次请求：展开一篇笔记是一次 `strix_note_get`。本地服务，代价是毫秒级，换来的是
  正文不必常驻内存。
