# ADR 0008：会话能做，画面不能做；以及面板上「什么该盖住」

- **状态：** 已接受
- **日期：** 2026-11-18
- **背景：** 插件 `todesk` 0.4.8；ToDesk 4.8.8.4；Astravia Desktop 0.5.97
- **修订：** [ADR 0006](adr-0006-screen-lives-in-todesk-window.md) 的界面部分（掩码规则被用户否决，见第三节）

## 一、对话式远控：满足到哪一步

用户要的是「在宿主对话框里用 AI 对话控制另一台电脑」。拆开成三层，逐层给答案：

| 层 | 对话里能不能做 | 依据 |
| --- | --- | --- |
| **会话生命周期**（读设备码、发起连接、断开、开关自启、调出窗口） | ✅ 能，已有 5 个工具 + 本轮新增技能 | `ToDesk.exe -status/-control/-exit/-autostart` 是官方文档命令，实测可用 |
| **会话内的画面**（看到远端桌面） | ❌ 不能 | ToDesk 没有截图 CLI；带截图的接口只在它的 MCP 里，而那个端点从不监听（ADR-0005 已删） |
| **会话内的输入**（点按钮、敲键盘） | ❌ 不能 | 同上：鼠标/键盘事件只存在于 `todesk_gui_*` / `todesk_send_*`，都走 MCP |

**所以本轮补的是第一层，并且明确把第二、三层挡在门外**：新增 `agent/skills/todesk/SKILL.md`，让 Agent 知道何时调用、按什么顺序调、以及**不许**声称「我连上并在那台机器上做了 X」。

三个候选补法及取舍：

| 方案 | 做法 | 结论 |
| --- | --- | --- |
| A. 宿主截屏 + 合成输入 | 用 `capture.offscreen` 截 ToDesk 窗口，再向窗口注入鼠标键盘（Win32 / PowerShell） | **不做**。需要额外命令授权（powershell）、像素级坐标对齐、且一旦 ToDesk 换渲染就整体失效；等于在插件里手搓一个远控客户端。 |
| B. 等 ToDesk 开放 | 只在通道可用时暴露原生 34 工具 | **保留**。代码里没有 MCP 依赖，将来 ToDesk 真开了它能直接受益。 |
| C. 只用生命周期 + 说清楚边界 | 工具 + 技能 + 面板文案 | **采纳**。 |

## 二、工具与技能的职责切分

- **工具**负责动作：`todesk_status` / `todesk_connect` / `todesk_autostart` / `todesk_open_client` / `todesk_disconnect`。
- **技能**负责判断：先 `status` 确认客户端在跑；出站必须同时拿到**设备码 + 临时密码**；失败话术怎么读（`host_error: …command disabled by user…` = 宿主没授权命令）；以及那条硬边界。
- `todesk_connect` 的 `password` 从「可选」改成 **required**：ToDesk 对别人的机器就是要密码，可选参数只会让 Agent 发出一个注定失败的调用。

## 三、面板：只盖住密码

用户否掉了「设备码默认掩码」：

> 自己电脑的设备码不再掩码，只有自己的临时密码才需要掩码。

这与产品事实一致——设备码是公开标识（你念给对方听的那串数字），密码才是凭据。所以：

| 元素 | 之前 | 现在 |
| --- | --- | --- |
| 本机设备码 | `••••••789` + 显示按钮 | **明文**，可复制、可刷新 |
| 连接目标的设备码 | 回显掩码 | 明文 |
| 「最近一次命令」 | 掩码 | 明文 |
| 密码 | 可选，藏在按钮后 | **必填**，`type="password"`，行内小眼睛可看 |
| 布局 | 设备码一行、密码另起一段 | **设备码 ｜ 密码 ｜ 连接 同一行** |

代码侧删除了 `domain/mask.ts` 及其测试：掩码不再是这个插件的规则，只保留输入框的 `type="password"`。

## 四、代价

- 密码进了 `-passwd` 参数后会出现在进程命令行（ToDesk 的接口如此），面板不做假承诺；副作用是本机进程列表可见，已在 README 写明。
- 技能被设为 `defaultVisibility: hidden`：它是「怎么用这个插件」的说明书，不该在技能选择器里和通用技能抢位置，但仍然随插件安装并被 Agent 读取。
