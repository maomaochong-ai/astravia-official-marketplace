# 画布内置技能库清单（73 个）

本清单是上游 `open-ai-canvas` 内嵌技能库的快照，用来回答两件事：画布到底带了哪些技能，以及
每个技能的稳定 ID 是什么。插件不复制这些文档，只通过 MCP 工具按需读取——为什么这样定，见
[ADR-0016](./adr/open-ai-canvas/0016-canvas-skill-library-toolset.md)。

## 来源与统计

- 来源：上游仓库 `backend/builtin/`（`//go:embed all:*`，编进后端二进制）
- 抓取时间：2026-10-28，共 **73** 个技能目录（外加 `embed.go`）
- 元数据取自每个包的 `SKILL.md` frontmatter：`name`、`description`、`metadata.skillId`、
  `metadata.tag`、`metadata.version`、`metadata.sortWeight`
- 分类分布：短剧影视 26 / 创意设计 24 / 电商营销 12 / 社媒内容 8 / 其他 3

## 怎么用

技能由后端提供，插件把它投影成 8 个 MCP 工具：

| 工具 | 用途 |
| --- | --- |
| `list_skills` | 分页浏览 / 关键词搜索 / 按分类与排序筛选 |
| `get_skill` | 取 `SKILL.md` 正文（默认截到 20000 字符，带截断标记） |
| `list_skill_files` | 列出包内文件（`cards/`、`references/` 等） |
| `read_skill_file` | 读包内某一个文档 |
| `search_skill_files` | 在包内按关键词定位段落（上游限 50 条命中） |
| `list_added_skills` | 看自己装过哪些 |
| `set_skill_added` | 加入 / 移出「我的」 |
| `list_skill_presets` | 按场景取预设技能组合 |

两条使用要点：

1. **`skillId` 才是主键，目录名只是可读 slug。** 例如 `图片图层拆分` 的 `skillId` 是
   `yingce-image-layer-split`，`分镜语法` 是 `16000000000094`。传参一律用下表 ID，不要猜目录名。
2. **复杂技能的知识不在入口文件里。** `影视剧作工坊` 有 246 个文档、`喜剧 Mechanics` 68 个、
   `体验设计五原则` 58 个。只读 `SKILL.md` 会漏掉 `cards/` 里的工艺卡，需要时用
   `list_skill_files` 再按需 `read_skill_file`。

## 字段说明

- **文档**：包内 `.md` 文件总数（含 `SKILL.md`）。1 表示只有入口文档。
- **结构**：包内的组织方式。`cards/` 是知识卡，`references/` 是参考资料，
  其余为上游自建的分模块目录。
- **一句话用途**：`description` 的第一句，便于扫读；完整描述（含触发条件）用 `get_skill` 取。

## 维护：上游新增技能时怎么更新这份清单

清单是抓取结果，不是手抄本。留意这几处会变的地方：

1. **数量与分类**：以 `backend/builtin/` 的目录数为准，重新统计 `metadata.tag` 分布并更新本页
   顶部两处数字。
2. **命名**：`name`（展示名）与目录名不一定相同（`ai-表演实验室` → `AI 表演实验室`，
   `喜剧-mechanics` → `喜剧 Mechanics`）。目录名只是 slug，别把它当 ID 写进文档。
3. **版本**：目前只有 `影策短剧制作工作流`（1.4.0）、`影视剧作工坊`（1.1.6）、
   `豆包音频提示词`（1.0.1）不是 1.0.0，其余都是 1.0.0。
4. **结构**：新增技能如果带 `cards/`、`references/` 或自建模块目录，要体现「结构」列，
   否则读者会以为只读入口文档就够。
5. **工具面是否要跟着变**：新增技能不需要改插件——工具是通用投影。只有当上游改了
   `/api/skills*` 的路径或参数，才需要动 `server/src/canvas-skill-library.ts` 与
   `scripts/verify-mcp-tools.mjs`。
