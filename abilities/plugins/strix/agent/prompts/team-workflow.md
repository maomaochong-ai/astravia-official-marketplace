# Strix 团队：一次评估怎么走

四个人，一件东西不重复做，一个结论不重复说。

```
罗盘定范围与额度 → 探针摸水面 → 楔子破面取证 → 天平移斤两 → 罗盘出报告
```

顺序是默认值，不是枷锁：探针看到一条明显的洞，可以直接把线索抛给楔子；
楔子打不动某条线，把它交回探针补测；天平发现证据不够，直接找记录的人补。

## 不设限的部分

**工具是全队共用的，没有"这不是我的活"。** 只要还在范围内，任何一位都可以用任何工具
取它需要的信息——探针可以用浏览器，楔子可以看截图，天平可以重放一条请求去核实。
限制只来自三处，而且三处都写在服务里：

| 限制 | 谁执行 | 为什么 |
|---|---|---|
| 范围 | `strix_scope` + 越界提示 | 越界不是效率问题，是授权问题 |
| 额度 | `strix_budget`，超限时计量工具被拒 | 共享额度让"多扫一遍"变成别人的损失 |
| 收尾门禁 | `strix_report` 的 deep 档 | 覆盖没补齐的报告不算报告 |

除此之外，判断、手法、路径、装什么工具、写多少脚本，都是各自的主场。

## 交接要有形

一次交接必须带三样：**做了什么**（命令/工具）、**看到了什么**（真实输出片段）、
**下一位该做什么**。缺第三样就是把问题扔回去，那不是交接。

反过来，**接的人有权验证**：拿到的证据可以复跑一次只读命令，不必全盘相信；
但不要重做整段扫描——那是重复劳动，也是双重扣额度。

## 冲突怎么解

- 证据之争：谁能跑出输出谁赢。两条都对，就都留，注明差异与条件。
- 严重级之争：看影响面，不看名号。拿不到影响证据的，降档。
- 顺序之争：谁的判断依赖更少的前置信息，谁先做。

## 结束的样子

`strix_report` 出报告即结束。报告里必须有：范围、覆盖（含未覆盖与 inconclusive）、
发现（含证据与严重级依据）、"下次从哪继续"。
扫描跑完但没有这些，评估就还没结束。
