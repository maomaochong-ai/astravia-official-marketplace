# 博思 AI

页内 AI 就是那个「按一句话改画布」的 agent（`docs/adr/boardmix/bm-0003`）。
插件不是它，也替代不了它；插件能把**一句写清楚的 prompt** 送到它的输入框里，并在用户明确要求时按下发送。

**三个地址其实是同一页。** `/ai/chat` 与 `/ai/ppt` 都 redirect 到 `/agent`。`boardmix_ai` 的三个 `kind`
是同一个落点的三种意图，不是三张不同的页面——不要告诉用户"打开了三个不同的 AI"。

## 一件事：prompt 才是交付物

一次导航本身产出为零。让它变成产出的，是这句话里有没有这三样：

| 要素 | 反面例子 | 正面例子 |
| --- | --- | --- |
| 主题 | 「做个PPT」 | 「Q3 增长复盘」 |
| 受众 | —— | 「给管理层看」 |
| 长度/结构 | —— | 「8 页：背景、三条结论、下一步」 |

`boardmix_ai_prompt` 会替你挡住明显不合格的（少于三项里的两项就拒收，`reason` 里说明缺哪一项）。
被拒不是失败，是它在替你省积分。

## 两步，顺序不能倒

```json
{ "prompt": "…写清的 prompt…", "kind": "deck" }
```
→ 输入框里有字、**没有发送**。`delivered: true` 才算放进去。

```json
{ "prompt": "…", "kind": "deck", "send": true }
```
→ 只在用户说了「你来发」「直接生成」时用。这句话花的是**用户账户里的积分**。

- `composer: { composer, viaPaste, preview }` 告诉你找到了哪个输入框、用的是粘贴还是插入命令。
  中文只能走粘贴（`type` 是真实按键，没有输入法）。
- `delivered: false` 且 `reason: "no-composer"`：页面还没渲染完，或改版了。**不要盲打**——
  把 prompt 放进回复里让用户粘，或者用 `boardmix_read` 找到输入框再 `boardmix_act`。
- `sent: true` 只说明点了发送，不说明生成成功。

## 生成之后

1. `boardmix_shot` 拍一张，`Read` 那个 PNG——**AI 的产出只有截图能证明**。
2. 失败、排队、额度不足，都只能从页面上读；读不到就说读不到。
3. 不要描述"即将生成的 PPT 长什么样"。没有截图就没有结论。

## 积分

- AI 会员 10000 点/月；免费账户能试，但很快用完。
- 批量或明显重的请求，在跑之前说清成本，不要跑完再说。
- `send: true` 每次都在返回里重申"花的是用户积分"——把这句话转述给用户，不要省略。

## 与我自己画图的分界

| 用户要的 | 走哪条 |
| --- | --- |
| 「让 AI 帮我做一份演示 / 一份文档 / 一张插画」 | 这个技能：`boardmix_ai_prompt` |
| 「我给你这份 Mermaid，画到板上」 | `boardmix-diagram`：`boardmix_diagram` |
| 「把这段笔记变成流程图」 | 先自己写 Mermaid，再走 `boardmix-diagram` |

分界只有一句：**谁生成**。AI 生成 → 这里；我生成 → 那里。混着说，用户就不知道东西是谁做的。

## 完成的样子

- `delivered: true`，且用户知道发送这一步是谁按的；
- prompt 本身在回复里（用户能改、能复用）；
- 有截图，且你看过它；
- 说过积分归属。
