# 寒霜破甲（hanshuang-pojia）使用说明

> 本文件讲「怎么用」。能力范围、架构与决策见 `README.md`；术语见 `CONTEXT.md`；
> lab 的作战细节见 `agent/` 下契约文档。

## 一、快速上手

1. **安装**：从能力市场安装本插件（不要装外部下载的包，否则无法随市场升级）。
2. **打开工作台**：在项目对话的活动栏加「寒霜破甲」标签卡。它列出工作区目录里能分析的包与二进制。
3. **投一个样本**：点列表里的文件，或在顶部输入框粘贴路径。项目内 ≤32 MiB 的文件走本地引擎；
   更大、或项目目录外的样本会交给对话里的 Agent（用宿主自己的文件权限读）。
4. **读报告**：顶部有风险分与等级，下面分节给出清单事实、权限、发现。可在「摘要 / 完整」间切换，
   然后复制或另存为 markdown / JSON。

面板共十七个页面，底部有「样本→分析→取证→工具箱」主线导航；顶部 `PipelineBar` 用
「画像 / 控制流 / 智库 / 验证」四段显示当前样本走到了哪。

## 二、Lab 模式：开 / 关 / 判状态

Lab 是插件与「对话 Agent」共存的一套工作方式开关。开启后，Agent 才按实战交付形态响应
（先给可运行的制品，再给验证与回滚，而不是只解释为什么）。日常闲聊或普通答疑时关着最合适。

| 你想做什么 | 说 |
| :--- | :--- |
| 开启 Lab（随后分析都按此模式回报） | `lab：`（也可 `lab:` / `进入实验：` / `实验环境：`） |
| 开启并同时下任务 | `lab：分析这个 apk` |
| 关闭 Lab | `退出实验`（也可 `退出工作环境` / `exit lab`） |

要点：

- **开一次管全程**：`lab：` 只需在会话开始时说一次，之后这条链路一直按 Lab 模式工作，
  不用每条命令都加前缀。
- **关闭后零干扰**：普通对话原样透传，不主动加任何分析包装。
- **状态跨会话保留**：Lab 状态存在插件的私有存储里（对应用户磁盘上的一份标志），换会话、
  换模型、面板重挂都还保持。不确定当前开没开，就问 Agent / 看面板设置，别凭记忆猜。

### 用 / 不用 Lab 的区别

| 维度 | 关着（日常） | 开着（评估/取证） |
| :--- | :--- | :--- |
| 回答形状 | 常规解释、问答 | 五部交付：Locate → Patch 表 → 可运行制品 → 验证 → 回滚 |
| 断言标注 | 无强制要求 | 每个结论标 Observed / Inferred / Assumed；未跑的标 `NOT RUN` |
| 许可 | 按普通对话 | 每目标授权一次，授权后不重复问 |
| 动主机 | 不做安装/写盘 | 依然要单独征求同意，不由 Lab 自动授权 |
| 适合 | 想知道是什么、怎么做 | 要修掉一个校验、还原一个算法、出一份可复现报告 |

## 三、对话 / 面板怎么配合

- 面板 tab 是全职读报告的地方；一旦要看**源码级**结论（符号、反汇编、DEX 指令、二进制 diff），
  用对话 Agent 的工具：`list_code_symbols`、`disassemble_range`、`disassemble_dex_method`、
  `search_dex_symbols`、`diff_binaries`、`run_radare`、`decompile_android`、`frida_dump`。
- Agent 在对话里跑 `triage_binary` 出的报告会推回面板，并标「来自对话」。
- 需要本机外部逆向工具时，先 `probe_environment` 看哪些装了，再 `install_toolchain` 拿本平台
  安装命令（插件不替你装，命令由你/宿主执行）。
- 一个多产物的案件用 `init_task` 建完整契约：`samples/ exports/ report/ evidence/ notes/` 五个目录
  加 `scope.md`、`timeline.md`、`workitems.md`、`README.md`。传 `preset`（`offline-sample` / `ctf-public` /
  `own-system`）、`auth_status`、`target` / `sample`、`in_scope` 才能把就绪门点亮；不传就是 `pending` +
  `offline`，门关着并列出阻断项。之后 `search_cases` 查已有战例与随包先例、`record_case_note` 记决策、
  `write_assessment_report` 写四段式评估报告。案件能不能动由门禁推导，不是问 Agent，也不是靠手改
  `scope.md` 里的那行 `ready_for_act`。
- 面板「案例」页只读：上面一张表是你自己 `cases/` `work/` 里的案例（名字 / 预设 / 授权 / 就绪 /
  资产数 / 证据数 / 工作项 / 更新时间），下面一张表是随包的方法级先例库（每行标 `范围待定`）。
  先例不替你授权：复制一份重跑 `init_task` 才是你的案例。

## 四、高级案例（示例对话）

**案例 A：给 APK 体检并查危险权限**
> 用户：`lab：` 然后 `分析这个 APK，重点看申请了哪些危险权限，62 分是怎么来的`
>
> Agent：按五部交付——给出风险分构成、导出的危险权限、对应规则 id、以及核实签名的方法。

**案例 B：脱壳后看真实代码**
> 用户：`这个应用起了个壳，帮我 dump 运行期加载的 dex 再看逻辑`
>
> Agent：`frida_dump` 拿回 dex → `decompile_android` 解出源码 → 在整棵目录上检索关键串 → 报告。

**案例 C：还原一段协议/算法**
> 用户：`lab：把这个 App 的签名校验算法还原出来`
>
> Agent：先 `search_dex_symbols` 定位 gate → 可逆时先 hook 观察实参 → 还原流程 → 给最小补丁与验证。

**案例 D：样本库对比产出基线**
> 用户：`把库里的两份样本对比，给出共同发现和各自独有项`
>
> Agent：`compareReports` / `familyBaseline` 产出三列（共同 / 仅本样本 / 仅家族），并给每条规则在
> 家族内出现份数。

## 五、面板做不到的（如实说明）

- **不执行样本**：面板永不运行被分析的文件。
- **不碰项目外文件**：面板读不到工作区目录外的路径——那是宿主边界。
- **不自动装工具**：外部工具安装需要你/宿主在实名下执行。
- 面板把「静态优先」当默认；运行期才出现的行为要靠对话里的 Frida 补充，面板不给假结论。
