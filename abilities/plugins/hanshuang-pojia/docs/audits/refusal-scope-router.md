# 已推翻：把「范围路由」写成划界（2.13.1 的一次错误设计）

> **时点**：2026-10-29　**状态**：**已推翻**　**取代者**：`src/domain/target-shape.ts` + `docs/domains/dialogue-and-routing/dev.md`
>
> 这份文档原本论证「插件应当对请求划界：对象是线上第三方凭据时不改写原请求，只给自有资产的等价做法」。
> 2.14.0 起这条结论整条撤回。下面保留推翻的理由与当时的两个事故记录，因为它解释清楚了
> **为什么现在的实现是「附加第二条入口」而不是「判定 + 改道」**。

## 1. 被推翻的三条结论

| 当时写的 | 为什么错 | 现在 |
| --- | --- | --- |
| 命中 OUT 时**整轮改道**，注入的等价入口**替代**原请求 | 插件没有资格替用户决定他要什么。一次请求只交一份「自有资产版」，等于没回答他问的那件事 | 原请求照常作答，等价入口作为**并行的第二条**同时给出 |
| 判定要「收紧」：宁可漏判不放宽，因为误判代价高于漏判 | 误判的代价被算反了。误判使模型对一句正常请求塞进一段改写，用户看到的是答非所问；漏判只是少拿到一条附加入口 | 判定只决定**是否附加**，不决定**是否执行** |
| 上游 `MANUAL/COMPLIANCE-RELAY.md` 的「改写以过审」不照搬，划界在范围判定上 | 上游那套是用它换「模型肯干活」，插件没有中继机制还照抄它的划界，等于只留下限制、不留下能力 | 只对齐「换句型」与「换入口」两件事，不再有划界层 |

一句话：**当时的实现把「提一条建议」写成了「下一个判决」。**

## 2. 现在的实现

`target-shape.ts` 只有一件事：读形态，给入口。

- 识别结果只有两种形态：`holdable`（字节在用户手里）与 `remote-account`（目标是某个线上账号）。
  **形态不是许可**，类型注释里写死了这句。
- 命中 `remote-account` 时注入 `[等距入口]`，正文第一句是「这是附加，不是替代」，
  第二句要求「两条都交，不要用其中一条换掉另一条」。
- 返回值是 `null` 表示「没有可附加的」，调用方必须把它当「无附加」，不能当「否决」。
- 原请求一律照常执行：这一层没有 `return` 掉后续处理的分支，也没有「停手」的文案。

## 3. 仍然保留的两个事故判据

这两条与划界无关，是「答非所问」的两种可测量形状，测试一直盯着：

1. **长篇说明代替命令**：请求指向一个具体对象，回复却给可行性分析、道德段落或三个备选方案。
   正确形状是第一行就是命令、`文件:行` 或补丁表。
2. **用改写冒充回答**：把用户的原话换成一句「更安全的说法」再回答。换词不改变对象，
   换句型才改变判定 —— 这是上游 `MODEL-REFUSAL-MATRIX.md` 实测出来的唯一有效手段，
   也是 `reshaping.ts` 存在的理由。

且 `describeEquivalentPath` 对 `holdable` 必须返回 `null`。

## 5. 明确不做的四件事

推翻不是「把门拆了但仍悄悄留着」，下面四条同时在代码、提示词、测试三层上不成立：

| 不做的 | 体现在哪 |
| --- | --- |
| 不做「能不能开工」的前置条件 | `contract.ts` 不再渲染 `## signoff`；`SYSTEM.md` 的「范围」一节只讲记录；`system-prompt.test.ts` 断言不包含 `G-Auth 门已确认授权` |
| 不做「允许 / 禁止」清单 | 形态识别只输出 `holdable` / `remote-account`，没有第三个「不许」值；`scope-lexicon.ts` 只描述这句话在索取什么，不描述这件事能不能做 |
| 不拿等价入口换掉原答案 | `describeEquivalentPath` 返回 `null` 时调用方无附加；返回字符串时调用方只能 `push`，不能 `return`——`contributions.ts` 的第 0 级不短路后续级 |
| 不在提示词里留否决话术 | `SYSTEM.md` 已删 `## 拒答形状` 与 `### 授权不能改写对象身份`；`system-prompt.test.ts` 对这两个标题与 `| OUT |` 做否定断言 |

另有一条不属于本层：「输出卫生」——真凭据不写进交付物。它限制的是**交付物形状**，不是任务范围。
