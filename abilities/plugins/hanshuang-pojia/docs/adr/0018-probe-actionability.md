# 0018：拒答梯度要能「按下重测」，以及页头／侧栏的四处一致性

- **状态：** 已接受
- **日期：** 2026-11-20
- **背景：** 分两件事。一是拒答梯度对照表面上完整（有表、有建议、有按钮），但建议是点不动的标签，「改了写法有没有用」无从判断；二是样本 / 指南 / 侧栏三处各有一类一致性问题。
- **编号说明：** 0016 / 0017 已由同日的取证型侧栏可读性与全侧栏一致性标尺占用；本篇只记拒答梯度与页头／侧栏的改动，那四页的布局决定以 0016 为准。
- **适用：** `domain/refusal-probe.ts`、`tools/lab/probe-refusal.ts`、`components/prompts/probe-refusal-card.tsx`、`components/pages/{samples,guide,findings,strings,disasm}.tsx`、`components/shell/sidebar.tsx`

## 问题

### 一、拒答梯度：建议不可执行

| 现象 | 机制 |
|---|---|
| 表格里三枚「清单式重述 / 评审框架 / 英文重写」是纯 `<span>` | 点不动，也没有对应文本 |
| 无法按建议重测 | 面板没有把改写送进 `probe_refusal` 的路 |
| 重测之后看不出变化 | `PROBE_STATE_PATH` 每次覆盖写，只剩最后一次 |
| 表里没有「期望」列 | 第 3、4 档本来就是 `expect: risky`，缺这一列会把「如预期」读成「出故障」 |
| 三档建议对探测提示词本身不成立 | `reshaping.ts#reshape` 要求先从原话提具体审计目标（路径/文件名/包名）；探测提示词刻意不带目标，所以 reshape 对它们**必然返回 null**。第一版是把标签印上去，实质没有可执行内容 |

### 二、样本 / 指南 / 侧栏

| 现象 | 机制 |
|---|---|
| 选中样本滚出 picker 视野后不知道在分析谁 | 页级没有回显 |
| 指南页头三个 AI 按钮 | 窄面板换行成三行；`ai.toolchain` 与自检页重复 |
| 段卡副标题 `truncate` | 页名列表（最多 4 项）在 150px 里必然截断 |
| 侧栏收起后导航按钮没有 `focus-visible` | 键盘用户看不出焦点 |
| 分组标题 `uppercase` | 中文没有大小写，是空操作 |

## 决定

### 拒答梯度

#### D1 建议必须是可执行文本，且不依赖 reshape

新增 `rewritesFor(prompt)`：三档 **target-free** 改写（清单口径 / 评审框架 / 英文），把原问题整段嵌进去。
它不调用 `reshape()` —— 后者对探测提示词恒为 null，正是这条链路断掉的原因。改写**不保证通过**，但它可执行、可对比。

#### D2 每条被拦档位可「按下重测」

卡片里展开一条改写，三个按钮各对应一档；点击把文本送进对话，由 Agent 用 `probe_refusal { prompt }` 重跑同一端点。面板不自己发请求（它没有凭据）。

#### D3 记录带一份上一轮的结论

`ProbeRecord.previous?: ProbeSummary`：写盘前读旧记录，同模型 + 同端点才带进来。
面板据此显示「第 3 档 → 第 1 档：变差」这类一行对比。只留一层，不攒历史 —— 判据只需要「改之前 vs 改之后」。

#### D4 表格补齐「期望」与「命中类」两列

`expect` 决定读者该不该把这次拦截当成问题；`kind` 决定给哪一档改写（政策/转介多给一档）。两列都在 `renderTable` 里，面板却漏了，导致同一份数据在两个视图里读法不同。

### 样本 / 指南 / 侧栏

#### D5 选中样本在页级回显

一行显示路径 + 当前评分/等级。滚出 picker 后仍知道「正在看哪一份」。

#### D6 页头只留一个主动作

指南页头只保留「让对话继续」；`ai.report` / `ai.toolchain` 移进「下一步」卡底部 —— 它们都属于「让对话接着干」，和计划同处一卡。

#### D7 段卡副标题换行

`truncate` → `line-clamp-2`：页名列表本来就短，两行足够，不必截断。段卡宽度仍是文档化的 150px 硬下限（横向滚的语义依赖它），不改。

#### D8 侧栏可访问性与密度

- rail 态导航按钮补 `focus-visible:ring-2`；
- 分组标题去掉 `uppercase`（中文空操作），字号留在标尺的 9.5 档。

## 不做什么

- **不改段卡宽度 150px。** 工序线「一行到底」的语义依赖这个下限；改了就得重新算总宽度，而横向滚动本身已经是正确解。
- **不给探测加历史列表。** 只留一层 previous：这套功能的判据是「改之前 vs 改之后」，攒十份历史只是把问题推给读者。
- **不让面板自己发模型请求。** 面板没有凭据，也不该把密钥搬进渲染进程；重测统一走对话，密钥由 Agent 侧传入并在输出里打码。
- **不把 `empty`（服务端丢正文）也说成「换个写法」。** 两者的修复动作不同，混在一句建议里就是误导；`adviceFor` 早就分开了，面板沿用。
- **不给 `expect: risky` 的档位做「必须通过」的判定。** 第 3、4 档被拦是常态；把它当失败会让这套工具变成「找模型的茬」。
- **不引入虚拟滚动。** 反汇编输出改成 800 行 + 卡片吃剩余高度已经足够；虚拟滚动要动的是一整层渲染路径，收益与风险不成比例。
