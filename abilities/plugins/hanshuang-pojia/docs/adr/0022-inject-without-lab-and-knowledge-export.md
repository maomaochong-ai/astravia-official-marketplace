# 0022：注入出去的提示词不依赖 lab 开关；文档导出与筛选统一

- **状态：** 已接受
- **日期：** 2026-11-22
- **背景：** 三个来自实际使用的问题，前两个是「注入/导出这类一次性动作」的边界，第三个是一处筛选控件的分裂。
- **适用：** `components/pages/inject.tsx`、`components/pages/docs.tsx`、`components/pages/cases.tsx`、`components/shell/filter-menu.tsx`、`domain/prompt-templates.generated.ts`

## 问题

### 一、注入了系统提示词，但没在对话里打 `lab：`，会不会白装

`lab` 是**插件侧**的运行时开关（`domain/lab-mode.ts`，默认 `enabled: true`），它控制四件事：
每轮附加的 context（历史声明作废 / 交付形状 / 句式降级）、大系统提示块是否注入、22 个 lab-only 工具是否进工具表、`Stop` 侧的回续判定。

而「注入系统提示词」写的是**别的宿主**的配置文件（Codex / Claude / Cursor / OpenCode …）。那个宿主读不到本插件的存储，lab 开关对那份文本**完全没有作用**：注入的正文必须自己成立。

结论分两半：
- 在 Astravia 自己的对话里：lab 默认就是开，**不打 `lab：` 也有完整效果**；只有用户曾显式 `退出实验` 或面板关掉过，才会退化成「静态正文 + 核心工具」。
- 注入到外部宿主：与 lab 无关。脚本/正文已经落进对方配置，效果由那份文本自己决定。

风险不在「没打 lab」，而在**用户以为两者有关**。所以这条判断必须写在动手的地方。

### 二、案例库的筛选与文档页不是同一个控件

文档页是 `<details>` 下拉（图标 + 当前筛选名 + 带计数清单），案例库是一排 chip。
同一层工具栏里两种形态，读者读不出它们是同一件事；chip 在窄面板还要横滚，把计数挤出视野。

### 三、知识库的两处具体缺陷

| 现象 | 机制 |
| --- | --- |
| 进知识库就自己弹出预览 | 播种用的是 `docs.selected?.id ?? null`。索引异步加载，首帧 `selected` 为 null，于是 `useDocs` 加载完后**自己选中第一篇**被当成「外部选中」，弹窗自己开了 |
| 文档没有导出按钮 | 导出只存在于右键菜单里；菜单是「知道它在才找得到」的入口 |

## 决定

### D1 注入页写明 lab 无关性

注入页顶部加一行固定说明：注入出去的是静态正文，对方宿主读不到本插件存储，lab 开关对它不起作用；Astravia 内 lab 默认开、无需打口令。
**不改 lab 的默认值**，也不在注入的正文里塞 lab 指令——那会让外部宿主收到一条它无法执行的命令。

### D2 顺带补一个「复制正文」

宿主配置不在本机（远程 / 容器）时脚本跑不了，粘贴是唯一路径。复制失败要报错，不静默。

### D3 两个页面共用一个 `FilterMenu`

新增 `components/shell/filter-menu.tsx`：折叠态一枚胶囊（图标 + 当前筛选名），展开是带计数的清单；再点已选项 = 取消筛选。
案例库改用它；文档页保留两级列表（组 → 子目录），但胶囊外观与它一致。

### D4 文档预览只在「用户要求」时打开

把「播种」与「已打开」拆成两个 ref：首帧只播种、不打开；之后的选中变化才算外部跳转。
行内点击本来就直接 `setOpenId`，不受影响。

### D5 导出按钮放在工具栏，导的是**当前可见清单**

筛选了什么就导什么，搜索结果同样。单篇导出保留在右键菜单。
两个导出共用 `downloadMarkdown()`（Blob + `a[download]`，不经过宿主，因此不需要额外权限）。

## 不做什么

- **不在注入正文里追加 lab 说明句。** 对方宿主没有这个概念，加了就是噪音。
- **不把 `lab` 默认值改成 false 或「跟随注入」。** 默认开是刻意的：装完就能按手册干活。
- **不给文档页做虚拟滚动。** 目录是分组列表，不是长列表；`fb-scroll` 足够。
- **不让导出走 `fs.saveAs`。** 那是「用户选位置」的动作；知识库导出是「拿走一段语料」，浏览器下载更直接，也不需要额外权限。
