# 0025：注入为什么会被宿主丢掉，以及梯度按目标类别生成

- **状态：** 已接受
- **日期：** 2026-11-22
- **背景：** 三条都来自同一个方向的问题——插件把话交给宿主，宿主不一定照做。
  一是系统提示词注入可能被宿主模型本身丢弃；二是梯度发过去后宿主的句式都一样（僵尸句式），
  且对象类的挡位「全都不适用」；三是表格的列、命中类、措施与模型状态跟不上对话。
- **适用：** `runtime/contributions.ts`、`domain/probe-ladder.ts`、`domain/refusal-probe.ts`、`components/prompts/probe-refusal-card.tsx`、`hooks/use-live-probe.ts`

## 一、注入会被丢掉：宿主的动态注入机制是什么

先把机制说清（读的是宿主 SDK 与插件自己的 `runtime/contributions.ts`）：

| 层 | 机制 | 会不会被丢 |
| --- | --- | --- |
| `registerSystemPromptProvider` | 每轮**开始时**求值一次，返回值是操作序列（`addBlock` / `setToolEnabled` / `requestContinuation`），其效果在该轮的后续模型调用中**重放** | 不会被「下一轮覆盖」，但**只在 provider 被调用时**生效 |
| 块 + `enabled` | 宿主按 `priority` 排序拼进系统提示；`enabled: false` 的块不进 | 会——禁用状态一律丢弃 |
| `UserPromptSubmit` hook 的 `additionalContexts` | 与用户原话同一条消息送进去 | 会被丢——它是**上下文**，不是指令；模型可以无视 |
| 注入到**外部宿主**的静态文本 | 写进对方的配置文件（Codex / Claude / Cursor） | 完全取决于对方；本插件的 lab/开关对它零作用 |

真正的失效点有三个，都不是「宿主偷懒」：

1. **provider 没被注册**（权限未授予 / 激活顺序靠后）→ 整层不存在。这与 0011 里「装好没 tab」
   是同一类问题，已在 0017 的激活顺序里处理（每一步独立 try/catch）。
2. **块被禁用**（`enabled: false`）或 **lab 关闭**——`SYSTEM_PROMPT_BLOCK_ID` 只在 `lab.enabled`
   时加入，lab 关闭时只留 `CORE_TOOL_IDS`。这是刻意设计（ADR 0019 的「每轮预算」），不是缺陷。
3. **`additionalContexts` 被当作材料而非指令**——模型看到「[历史声明作废] …」这类句子，完全可以
   当成背景信息忽略。这是本插件最依赖、也最脆的一条：它靠**措辞**而不是结构生效。

### 决定

- **D1 结构优先，措辞兜底。** 能进「系统提示块 + 工具表开关」的东西不要塞进 `additionalContexts`。
  已有分工保持：硬约束（工具可见性、内核块）走 provider；逐条安抚（历史声明作废 / 交付形状）
  继续走 hook，但**不指望它改变行为**，只当作降低概率。
- **D2 关键事实用「可验证的东西」表达，不用形容词。** 例：与其写「请勿拒绝」，不如让模型手上
  有 `probe_refusal` 这个工具与一条明确的判定表——它能查、能算，就不需要"相信"一段话。
- **D3 注入前先自检。** `kb_checklist`/面板的自检页已列出 provider 与块状态；补一条：当
  `lab.enabled` 为真但 `SYSTEM_PROMPT_BLOCK_ID` 未出现在上一轮操作里时，面板显示「内核块未注入」。
  （本轮只记录，不新增探测通道 —— 需要宿主暴露 turn 级操作回执，当前没有。）

## 二、为什么梯度的每一档都「不适用」，以及句式僵尸

标准四档是**二进制/服务端**叙事：概念 → SQL 注入 → 本地许可 → 补丁。目标是一句网站会员限制时：

- 四档问的东西与对象无关（「本地许可证校验函数」对一个网页没有意义）；
- 三档改写用同一套开头（清单式 / 评审框架 / 英文），所以看上去是同一个句子换皮。

### 决定

- **D4 梯度由目标类别生成。** 新增 `domain/probe-ladder.ts`：`targetClassOf()` 判
  `web` / `api` / `app` / `file` / `generic`，`ladderFor()` 为每一类给出四档，**每档都点名目标**。
  网站类问「权益分层、前端判定点、服务端权威、旁路与修复」；接口类问「鉴权模型、BOLA/BFLA、
  越权路径、断言重放」。
- **D5 句式随档位换。** `rungRewrite(prompt, level)` 按档位取
  `boundary / evidence / review / contrast` 四种形状，**目标原样带进去**，原句附在后面便于对齐。
  表里新增「句式」列——整列一个名字，就说明改写没换形状。
- **D6 摘掉应用标识再判类别。** `com.example.app` 里的 `example.app` 是合法 TLD 域名，会命中
  WEB 规则；分类前先把反向域名式标识从文本里摘掉，剩下的再判。

## 三、表格跟不跟得上

- **D7 列扩展。** 新增「句式」列（逐档不同）与表头「对象」标签（整表前提）；原有
  `级别 / 提示 / 期望 / 判定 / 命中类 / 措施` 保留。
- **D8 改写可编辑、可直接发。** 展开区从「三个模板按钮」改成**一个可编辑文本框**：先给按档位的
  默认句式，用户可以改口径，再点「发送去重测」把草稿作为 `retest` 交回 `probe_refusal`。
- **D9 模型状态取当前选择。** 表头模型优先 `live.model`，其次 `record.model`，都没有才用
  `profile.model`；与宿主当前模型不一致时标「记录来自 <旧模型>」。切换模型时
  `followHostModel` 只在用户没手改过时跟随（ADR 0024 D4 不变）。
- **D10 实时数据列。** 对话里的 `<probe-report>` 块解析出的行同时用于表格与措施区
  （ADR 0024 D2 不变），新增字段 `shape` 参与「句式」列。

## 不做什么

- **不为了「不被丢」而堆重复句。** 同一句连写三遍不会提高遵守率，只会挤占上下文预算。
- **不给 `additionalContexts` 加优先级权重。** 宿主没有这个字段；伪造一个只会让维护者误解机制。
- **不让面板自己发模型请求。** 面板没有凭据；重测统一走对话。
- **不把「被拒」当成结论。** 无目标、无类别、无回复都不算拒答；表格宁可空着。
- **不自动改写用户的自定义梯度。** 只提供默认句式，改不改由用户定。
