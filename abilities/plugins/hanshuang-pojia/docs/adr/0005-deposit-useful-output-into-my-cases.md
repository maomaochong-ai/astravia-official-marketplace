# 0005：有用信息沉淀到「我的案例」

- **状态：** 已接受
- **日期：** 2026-11-19
- **背景：** 寒霜迭代待办第 5 项。宿主对话里产出的报告、表格、代码片段、拒答恢复路径，都要能被打标签并沉淀进案例库；条目结构 `{intent, hostPrompt, refusalSig, rewriteChain, model, artifactRef, tags}`
- **适用：** `src/domain/my-cases.ts`、`src/features/workbench/hooks/use-my-cases.ts`、`src/domain/storage-layout.ts`

## 问题

「沉淀」有两个已经存在的同名物，先分清：

- `cases/`（仓库里 19 个先例包）与 `work/`（案例工程）是**随包的只读战例**，由作者维护；
- 「我的案例」是**这台机器上真的做过什么**，按工作区存于 `workbench/workspaces/<key>/cases.json`。

本篇只谈后者。「递归沉淀」在这个语境里的意思不是「自动把所有输出都存下来」，而是「同一份东西被反复处理时累加而不是繁殖，并且沉淀出来的条目能反过来支撑下一次工作」。

## 决定

**D1：条目字段分两层，别混。**

| 层 | 字段 | 语义 |
|---|---|---|
| 身份与分析结果 | `id`、`name`、`sha256`、`size`、`format`、`grade`、`score`、`findings`、`highlights`、`at`、`lastSeenAt`、`seen` | `id = sha256[0:16]-size`，与样本库同口径 |
| 溯源（待办点名的七项） | `intent`、`hostPrompt`、`refusalSig`、`rewriteChain`、`model`、`artifactRef`、`tags` | 回答「当时想让模型做什么、它怎么回应的」 |

`intent` 是闭集 `triage | host | draft | manual`，决定 `hostPrompt` 有没有意义（面板自分析为空串）。

**D2：入口只有两条，都必须显式。**

1. 一份报告产出来（`record(report, provenance)`）—— 分析完成即入；
2. 用户把发送前编辑过的草稿按「存为案例草稿」（`recordDraft`）—— 还没跑也能留。

**没有第三条「自动把别的会话的东西并进来」的路。** 会话草稿在存储层是 `session` 作用域（见 0014），跨会话不可见的唯一解药就是用户在这一层显式沉淀。

**D3：去重按 `id`，不按 `sha256`。** 同一份字节的分析永远得到同一个 `id`，于是重复分析是 `seen += 1` + 更新 `lastSeenAt`，`at` 保持首次时间。只比 `sha256` 会让「同名不同大小」的两条互相覆盖。草稿的 `id` 是 `draft-<fnv(prompt)>`，同一段文字只留一条。

**D4：条目数量有界。** `MAX_MY_CASES = 60`，`upsertCase` 超限时丢最旧的（按 `lastSeenAt` 排序后截断）。读回来的数据可能是坏的：`sanitizeCases` 逐条校验，丢弃形状不对的条目而不是让页面崩，非数组一律当空；旧版本缺少的七项补默认值，**不丢弃条目**。

**D5：「有用」的判据必须写在代码里，不能留给感觉。**

| 判为有用 → 沉淀 | 判为无用 → 不沉淀 |
|---|---|
| 产出了一份 `TriageReport` | 模型输出的正文本身（拒绝话术、解释、道歉） |
| 用户显式保存的草稿（非空、去空白后长度 > 0） | 空文本 / 只有空白 |
| 一次「拒答 → 改写 → 干净收尾」的链路（`rewriteChain` 非空且该回合未以拒答结束） | 同一 `id` 的重复条目（累加即可） |

第三条是本篇新增的判据，它把「这次换问法真的有用」变成可沉淀的事实，也是 0018 的检索基础。

**D6：`refusalSig` 与 `rewriteChain` 是观测记录，不是重试计划。** 这条立场不变：记下它们不等于插件会拿它们去跨模型重试。0018 增加的是「同一工作区内、同一会话内换问法时的候选排序」，与跨模型重试是两件事，界线由 0018 显式划出。

## 不做什么

- 不把宿主对话的整段正文存进案例库。`refusalSig` 只留类型与命中的**片段**，不留整段回话 —— 存了就等于把拒绝话术二次传播一遍。
- 不在沉淀路径上做分析。沉淀是事后的，分析结果是当下的；写盘失败不影响分析本身。
- 不因为「记下了」就自动重试。

## 验证

现有：`src/test/cases/my-cases.test.ts` 覆盖报告折条目的 id 口径、无非 info 发现时退回摘要、重复分析累加次数、按最近分析时间倒序、超上限丢最旧、坏数据丢弃、非数组当空。

待补：`refusalSig` / `rewriteChain` 的写入与读回（含旧版本缺字段补默认值）、`intent` 闭集校验、以及 D5 第三条判据的沉淀触发条件。
