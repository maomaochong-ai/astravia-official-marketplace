# 0028 — 面板观感统一、共享右键菜单、对话观测与样本浏览面

- 状态：已采纳
- 日期：2026-11-22
- 相关：0024（实时对照表）、0026（拒绝后自动探测）、0027（六档梯度与两阶段闭环）

## 背景

这一轮的四条反馈都是「面板已经能用，但不像一个东西」：

1. **活动页的配色和面板其余部分不协调**，活动流左侧有一条竖线，行与行挤在一起；
2. 知识库的先例清单**没有右键菜单**（文档树有），也导不出整包；
3. 发现页在没有报告时**只有一个「去载入样本」**，对话里已经跑出来的结论一条都看不到；
4. 样本页全是圆角卡片，挤在一起；面板拖宽后卡片底部留一大片空白；
   而且除了「点一下就分析」，没有别的事可做。

这四条指向同一个结构问题：**同一个东西在不同页面有不同的形状**。
菜单两套、状态两套、说明两套 —— 于是每加一个页面就多一套要维护的样式与交互。

## 决策

### D1 强调色跟宿主走，不再自己写死一档蓝

`--fb-accent` 从 `color-mix(in oklab, var(--primary) 78%, var(--foreground))` 推导。

原先是硬编码 `#1f6feb` / `#7cb0ff`：宿主主色是靛蓝 `rgb(99,102,241)`，
面板里却是另一族蓝。两者在顶栏、侧栏选中态、宿主自己的按钮上同屏出现时，
读起来就是「两套设计」。

不用 `var(--accent)` 仍然成立：宿主把它定义成 `foreground` 10% 的合成色，
拿来做选中态会得到一片几乎透明。`--primary` 才是宿主真正的强调色。
混合前景色是为了把明度拉回可读范围 —— 深色主题下 `--primary` 单独用作小字偏暗。

### D2 活动流：中性底、无竖线、给行留呼吸

- `.fb-terminal` 的底色从「surface 掺 12% accent」改成 surface 阶内的深浅差：
  原来那块偏蓝的底在整屏中性色里像另一个应用嵌进来；
- 去掉每行左侧 2px 状态竖线：20 行就是 20 条彩条，与侧栏选中态、卡片描边互相抢。
  状态已经在符号（`✓ ▸ ✗`）与工具名的颜色上；
- 行内边距 3px → 5px，行间 2px，轮次之间 12px。两行一条的记录贴在一起时，
  读者分不清是一条还是两条。

### D3 一个 ContextMenu，三棵树共用

`hooks/use-panel-menu.ts`（坐标与钳位）+ `components/shell/context-menu.tsx`（渲染与键盘）。

- 基准是 `[data-panel-root]`，不是 viewport：面板只是活动栏的一格，
  `fixed` 会把菜单画到宿主界面上；
- 先按估算高度钳一次（第一帧就落在面板内），挂载后按**实测**高度再修正一次
  —— 行数是调用方给的，估算差一行就会越界；
- 分组、图标、右侧提示、危险色、上下键 / Home / End / Esc / 点遮罩关闭；
- 文档树、先例清单、样本列表都挂同一份，动作只差「对谁做」。

先例清单的导出分三档，对应三种真实诉求：**单篇**（正在读的这一页带走）、
**整包**（照着做的人需要上下文）、**清单**（几十条时先看目录）。
读不到正文的那一篇留一行标记，不静默跳过 —— 少一篇而没有提示，
读者会以为那份本来就是空的。

### D4 发现页 = 对话观测 + 规则命中

`observations.ts` 把五个来源（报告 / 活动流 / 任务流 / 时间线 / 探测记录）压成最多 8 行，
顺序即决策优先级：**被拦 / 出错 → 探测结论 → 风险 → 本轮动态 → 最近结果 → 没有样本**。

- 纯函数，`t` 作为参数传入（与 `timeline.ts#turnLabel` 同一做法），所以可断言；
- 不造事实：没有数据就没有那一行，不写「一切正常」；
- 每行最多一个动作：跳面板（活动 / 探测 / 样本）或交给对话（把这一条作为上下文继续问）；
- 失败只取最近两条：第三条之后的意义是「去看活动流」，不是再读一行；
- 「零发现」也是一个结论，用 idle 行说出来，而不是留空。

### D5 样本页：一张卡、两个格

`.fb-samples` 用 `grid-template-areas` 把列表与说明放进同一张卡：
窄面板 `"list" / "detail"`（说明在页脚、自带高度上限），宽面板 `"list detail"`（并排）。

上一版是两个格子里各放卡片：说明那边只有三五行，格子剩下的高度全空着 ——
这就是「卡片底部大量无用空间」的成因。说明变成整列之后，内容短时的空白属于列本身，
看上去是边栏，不是「卡片没长满」。

列表里一行一个文件，不再是 19 张圆角卡：

- 已分析的文件直接在行上显示得分与等级，并可一键重开报告（与「我的库」同一份数据）；
- 行内「交接」走 handoff 对话框（与样本页原有那一条同一份 `buildPrompt`）；
- 行内「更多」与右键是**同一份菜单内容**（`sampleMenu(path)`）——
  两份各写一遍必然只修一处；
- 顶上有名字过滤与「只看已分析」，计数是「当前 / 全部」；
- 手动路径输入保留：宿主只列一层目录，样本常在子目录里。

## 后果

- 少了一套菜单实现、一套说明卡布局、一套强调色；
- `check-css.mjs` 的关键选择器清单从 `.fb-samples-picker` 改成
  `.fb-samples-list` / `.fb-samples-detail` —— 门禁必须跟着真实结构走，否则它保护的是不存在的规则；
- 时间线从「三处各算一遍」收进 `model.timeline`：三处判据不同就会对同一轮说出不同的话；
- 面板的强调色从此由宿主主题决定。宿主换主色，面板跟着换，这是期望行为。

## 不做什么

- **不重写文档树的搜索 / 预览**：这一轮只把菜单换成共享实现，行为不变；
- **不把观测行做成可以「执行」按钮**：面板没有凭据、也不该替用户发请求（同 ADR 0026）；
  它给的是入口与一句话上下文，真正的执行留在对话里；
- **不给样本行加「删除」**：样本是工作区里的文件，面板只读（ADR 0007 的边界）；
- **不在宽屏强制两栏**：760px 以下说明会挤成一句话一行，此时页脚形态更好。
