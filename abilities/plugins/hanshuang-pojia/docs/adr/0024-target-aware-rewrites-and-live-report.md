# 0024：改写要带目标；对照表以对话为准，模型切换要跟随

- **状态：** 已接受
- **日期：** 2026-11-22
- **背景：** 两处来自实机反馈：改写出来的句子是「demo」（用户写的目标在改写后消失）；对照表在宿主回答之后不更新，且换模型后仍显示上一个模型的结论。
- **适用：** `domain/refusal-probe.ts`、`components/prompts/probe-refusal-card.tsx`、`hooks/use-live-probe.ts`、`components/pages/prompts.tsx`

## 问题

### 一、改写不带目标

`rewritesFor(prompt)` 的三档只在**换口吻**：把原句塞进「我在整理一份检查清单 / 我在做设计评审 / 英文版」。用户的诉求是具体的（`www.aqiyi.com` 免登录看会员视频），改写后只剩「下面这个场景」——拿去重测等于测了一个别的问题，所以体验上就是 demo。

### 二、对照表不跟对话

表格只读 `probe_refusal` 写的文件。而实际使用里最常见的路径是：简报发进对话 → 宿主直接用它自己的模型回答（逐档拒答情况 + 措施）→ **没有调用工具**。于是文件不更新，面板停在上一份，用户以为「插件没生效」。

### 三、换模型后信息不准

- `hostModel` 快照会更新（每轮写），但 `profile.model` 不会跟着变，于是「要测谁」还停在旧模型；
- `record.model` 是上一个模型的结论，面板却不标注，用户按它判断就是被误导。

## 决定

### D1 改写必须携带目标

`probeTargets(prompt)` 抽出三类目标：域名（`www.aqiyi.com`）、反向域名式应用标识（`com.example.app`）、文件路径/文件名。
**域名与应用的区分靠形状**：应用标识的第一段是 TLD（`com` / `org` / `cn` …），域名不会以 TLD 开头。两个正则都能命中同一个字符串，所以分类不能靠先后顺序。

三档改写各自把目标写进去（`对象：目标站点 …` / `Target: …`），并保留原句便于对齐；抽不出目标时**明说**「这句话没有可识别的具体目标」，而不是假装有。

### D2 对照表以对话为准

约定一个机器可读块：

```
<probe-report>{"model":"…","rows":[{"level":1,"name":"…","verdict":"refused","kind":"policy","text":"这一档原句","advice":"这一档的改写措施"}]}</probe-report>
```

- 简报末尾明确要求 agent 回完拒答分析后附带它，并给出形状；
- 面板从**最新一条助手消息**里解析（只看最后 6 条），解析成功就覆盖显示；
- 解析失败或没有块就退回工具记录，并在表格顶部标出来源（`对话` / `记录`）——用户永远知道在看哪一份；
- 未知 `verdict` 按 `answered` 处理：宁可少报一次拦截，也不要把正常回答标成拒答。

### D3 措施可执行

措施区把「记录里的 advice」与「live 行自带的 advice」统一成一张表，每条附「发送」按钮：把该档的改写文本作为 `retest` 交给 `probe_refusal` 再跑一次。措施是结论，但它的价值在于能被执行。

### D4 模型切换要跟随，但不能覆盖用户的选择

`followHostModel(profile, previous, next)`：只有当 `profile.model` 为空**或正好等于上一个宿主模型**（即那一格一直是自动填的）时才跟随。用户自己敲过模型就不动——否则会把他正在测的端点悄悄换掉。

记录与宿主当前模型不一致时，表头显示 `记录来自 <旧模型>`，并说明按它判断会误导。

## 不做什么

- **不用代码围栏承载实时块。** 围栏会与正文里的示例表格混淆；尖括号标签只有 agent 主动写才会出现。
- **不在面板里解析自由散文。** 靠自然语言猜「哪档被拒」是不可靠的；要么工具写文件，要么给结构化块。
- **不把 live 数据写回文件。** 面板只是读者；写盘仍只有 `probe_refusal` 一个入口，避免两处写同一份记录。
- **不自动把 `profile.model` 改成宿主模型。** 探测的目标可以是任意端点；自动改会把「我在测另一个模型」变成静默错误。
