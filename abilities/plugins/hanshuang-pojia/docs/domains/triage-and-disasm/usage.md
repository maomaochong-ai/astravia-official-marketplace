# 静态体检与反汇编 · 怎么用

你手上有一个文件（`.exe` / `.dll` / `.so` / `.dylib` / Mach-O / 固件切片），想知道它是什么、
有没有壳、风险多高、某个函数在做什么。这一域**不运行样本**，全部在浏览器侧读字节。

开发侧地图见 [dev.md](dev.md)。

## 一句话触发

直接把路径丢进去就行，不需要先解释「我想做静态分析」：

```text
体检一下 /path/to/target.bin，它有没有壳？
这个目录里哪个文件最可疑：/path/to/dump/
0x1a3c 附近这段在干什么？文件是 /path/to/a.so
这个 exe 和上一版差在哪？/path/to/old.exe /path/to/new.exe
```

## 你会拿到什么

| 你问的 | 拿到的 | 说明 |
| --- | --- | --- |
| 这是什么 | 格式、SHA-256、大小、熵、节区、导入 / 导出表、0–100 风险分 | 首轮永远从这开始，30 秒内出结果 |
| 先看哪个 | 按风险排序的目录表 | 上千个文件时别逐个点 |
| 有没有端点 / 密钥 / 路径 | 命中字符串 + offset | offset 可以回填到节区 |
| 这段字节是什么 | 逐条反汇编 + 分支目标 | AArch64 精确；x86 是实用指令子集，未知编码显示 `.byte` |
| 这个函数干什么 | 寄存器级伪 C，带 `L_<offset>` 基本块 | 不是 Hex-Rays，别当源码引用 |
| 两版差在哪 | 字节级 hunk / 函数级 same·constants-only·changed | 补丁验证就看 `constants-only` |
| 这条发现严重吗 | 规则口径 + 该做什么 | 解释与规则表同源 |

## 分寸：什么时候够用，什么时候不够

- **够用**：定性（是不是加壳）、定位（哪个函数在判）、取证（字符串与偏移）、补丁前后差分。
- **不够用，必须换手段**：
  - 壳把节区打散、熵逼近 8.0 —— 先脱壳（Android 走 `frida_dump`，原生走动态 dump），再回来体检；
  - 符号被 strip 且没有导入表可依 —— 靠字符串交叉引用定位，不要指望函数名；
  - 需要真实控制流（虚表、间接跳转、VM 保护）—— 伪 C 跟不动，上 IDA 桥或动态观测。

## 面板对应页

- **体检**（triage）：格式、节区、导入导出、风险分与命中规则。
- **反汇编**（disasm）：填地址范围就渲染；`mode` 选 `full / fold / summary`，`fold` 只看分支、调用与比较，长函数用它。
- **字符串**（strings）：可搜、可按 url / path / identifier 过滤。

## 常见坑

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 反汇编出现大量 `.byte` | 架构判错，或起点落在数据里 | 显式指定架构；先用节区表确认代码段 |
| 只有文件偏移，没有虚拟地址 | 渲染时没传地址映射 | 面板里打开地址映射，页头会同时给 `file+0x…` 与 `vaddr` |
| 风险分很高但细节很空 | 就是壳 / 压缩 / 加密的典型形状 | 别急着读字符串，先脱壳 |
| 整段扫几 MB 卡住 | 线性扫描本来就不找函数边界 | 从符号 / 交叉引用 / 入口点给起点，一次一段 |
