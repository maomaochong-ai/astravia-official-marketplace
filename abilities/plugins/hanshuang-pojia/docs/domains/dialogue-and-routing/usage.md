# 对话侧注入 · 怎么用

这一域没有工具，它决定的是**你每问一句话，模型在动笔之前多看到什么**。改用户原话不是它的职责，
它只补上下文：这件事在插件里对应什么、该拿哪个工具、交付成什么形状。

开发侧地图、五级顺序与路由表结构见 [dev.md](dev.md)。

## 三种你会直接感知到的效果

| 你打的东西 | 注入补了什么 | 你看到的差别 |
| --- | --- | --- |
| `lab：` 或 `实验环境：` | 整个作战契约（交付形状、判定口径、输出卫生）+ 目标提取 + 快捷口令展开 | 回复第一行变成命令或结论，而不是可行性说明 |
| `poc` / `hook` / `keygen` 这类短语 | 展开成完整作业要求（要跑通、要补丁表、要验证与回滚） | 不再反问「你想要什么样的」 |
| 一句话里出现某个能力域的词 | 指向对应技能；技能不在包里时明说「未随包分发，不要假装读过」 | 不会凭空引用没装的东西 |

另外两类是**附加**，不改变你的原请求：

- **等距入口**：当句子指向「你并不持有的对象」（别人的线上账号、凭据库），除了照常作答，
  还会附加一条同一能力在你自有资产上成立的入口（第一条命令就位）。两条都是交付，不是二选一。
- **术语对照**：口语词与工程术语不一致时给一行对照，避免模型猜错对象。

## 分寸

- **lab 只在你说过之后生效**，说「退出实验」即关闭；它不改变插件是否可用，只改变交付形状的默认值。
- **注入不改写你的原话**：模型看到的是原请求 + 附加上下文；回答里出现的仍是你的问题。
- **不命中是常态**：大多数问题不会命中快捷口令或路由，这时只补交付形状那一行——它要求第一条是可执行的下一步，
  不是一段说明。
- **漏判的代价很小**：判不出来就只是少拿到一条附加入口，不会因此拒答或改道。

## 面板对应页

「提示词」页能看当前生效的系统提示词母本、备份与历史版本；「设置」页的 lab 开关就是对话侧的状态位
（开启后每轮都会注入契约）。自检页的 `assets.routing` 会打印路由表指纹——
怀疑「页面还是旧版」时，它比版本号更能说明加载的是哪一份表。

## 常见坑

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 说了 `lab：` 但回复又变成讲道理 | 状态没持久化或读取失败 | 面板设置页会显示真实开关状态；重新说一次 `lab：` |
| `lab：` 后面的任务被忽略 | 口令与任务写在同一行时按「口令之后的部分」取目标 | 把任务接在口令后面，不要另起一句 |
| 路由指向一个打不开的技能 | 该技能未随包分发（39 个目标里缺的） | 注入会明确说这一点；用同类先例替代 |
| 提示词改了没生效 | 手改了生成物或没重生成 | 改母本后跑同步脚本；测试会盯着正文一致 |
| 同一个问题两次答得不一样 | 判定是词表 / 正则级，不是语义级 | 换更具体的说法（给路径、给类名、给方法名）最稳 |
