# 外部 MCP 服务器 · 怎么用

插件自己**不需要** MCP：31 个工具都是宿主原生工具，直接读字节、直接给结果。外部 MCP 只在
「插件不拥有的能力」上才有意义——真要驱动 IDA Pro、要开浏览器、要跑别人的 JS 逆向链。

开发侧对照表与可粘贴配置见 [dev.md](dev.md)。

## 决策顺序

```text
这件事插件能不能自己干？
├── 能（体检 / 反汇编 / DEX / 签名 / 脱壳 / 知识库 / 报告）→ 不要装任何 MCP
└── 不能
    ├── 需要 IDA 的交叉引用与反编译器 → 装 ida（IDA 侧要先起桥，默认 127.0.0.1:13337）
    ├── 需要真实浏览器（登录态、截图、交互）→ 装 playwright
    └── 需要还原前端签名链 → 装 js-reverse
```

上游还带了一个把 r2 / jadx / apktool 包成 MCP 的 `seep` 服务器——**这里不要装**：同一批能力已经是插件原生工具，
再包一层只会让模型两边各调一次，还多一处版本漂移。

## 你会拿到什么

| 需求 | 装了之后 | 没装时 |
| --- | --- | --- |
| 「IDA 那头连上了吗」 | 只是一行状态：在听 / 不在听（不启动、不驱动、不读许可） | 同一行状态，永远不在听 |
| 深反编译、结构体、交叉引用 | 借 IDA 的反编译器 | 用 r2 的伪 C（能跟控制流，没有类型恢复） |
| 页面登录态、动态渲染 | 浏览器自动化 | 只能做静态分析 |
| 前端签名链 | 专用逆向工具 | 用知识库里的方法自己补环境 |

## 分寸

- **先证明插件不够用，再装**：`run_radare` 已经能给的（伪 C、交叉引用、字符串），装 IDA 不会更准，只会更慢。
- **装 MCP 不改插件权限**：它们的生命周期由宿主管理。插件只在你问的时候报一个状态。
- **路径是占位**：IDA 的 Python 解释器必须是 IDA 自带那一份，用系统 Python 会在桥接时崩。

## 常见坑

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 装好 IDA MCP 但插件说离线 | 桥没起（插件不起它） | 在 IDA 里启动桥；确认端口是 13337 |
| 模型把同一件事调两遍 | 同时装了 `seep` 与插件原生工具 | 删掉 `seep` 那份配置 |
| 浏览器 MCP 起来就崩 | 用了 `--extension` 但没装扩展 | 按该 MCP 的说明先装扩展，或改用非扩展模式 |
| 明明不需要却装了三个 | 没先走上面的决策顺序 | 只留真正缺的那一个 |
