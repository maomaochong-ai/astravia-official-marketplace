# 破甲研究流水线

五个阶段，串行。上一阶段的产出是下一阶段的输入；不通过就回到上一步，最多三轮。

## 1. 探针测试

**做什么**：对目标模型发一组探测，记录「哪些请求被拒、以什么形式被拒」。

- 覆盖三类架构：身份系统型、混合帧型、轻量型。
- 每个探针只改一个维度（人称、语域、任务包装、输出结构），否则拒答原因无法归因。
- **产出**：`probes.md` —— 探针文本 + 原样回复 + 是否拒答。
- **通过判据**：至少 20 条有明确结论（拒 / 不拒），且拒答样本不少于 5 条。

## 2. 拒答模式分析

**做什么**：读第 1 阶段的拒答样本，归纳拒绝的**触发面**。

- 分类维度：触发的词、触发的结构（"我不能"开头 / 结尾免责 / 替代方案菜单）、触发的层（内容 vs 身份 vs 政策）。
- 找出「同一请求换一种包装就被接受」的那些对照组 —— 那才是可用的缝隙。
- **产出**：`analysis.md` —— 触发面清单 + 每个触发面对应的可通过写法。
- **通过判据**：每个触发面都能指到至少一条具体样本。

## 3. 定制破甲词生成

**做什么**：按第 2 阶段的触发面写注入正文。

- 写成**契约型**：规定输出形状、缺参占位、证据分层；不写「请忽略限制」这类要求模型破例的句子。
- 有明确边界的禁止项放在最前面，且只覆盖它自己那个对象。
- **产出**：`words.md` —— 注入正文（可直接用于标记块或系统层）。
- **通过判据**：正文里没有一句是要求模型「破例」的；禁则都有明确对象。

## 4. API 验证

**做什么**：用同一批探针在新配置下重放，对比第 1 阶段。

- 同模型、同温度、同探针；只换注入层。
- 记录仍然被拒的类别 —— 那些是模型层的结果，不是提示词能改的。
- **产出**：`verify.md` —— 前后对照表 + 仍被拒清单。
- **通过判据**：可归因的提升（哪几条从拒变成接受），且有反例。

## 5. 三件套交付

**产出**：

| 文件 | 内容 |
|---|---|
| `words.md` | 可直接装的注入正文 |
| `manual.md` | 使用手册：帧矩阵（哪类请求配哪套写法）+ 推回词库（被拒时的下一句） |
| `report.md` | 研究报告：阶段记录、对照数据、失效边界 |

**通过判据**：三份都在，且 `manual.md` 的每条建议都能在 `verify.md` 里找到依据。

## 诚实边界

提示词只能改变「指令被放在哪一层」和「它有没有被当成可驳回的对象」。
模型层训练出来的拒答倾向，换提示词无效 —— 那一步只能换模型。
研究记录里必须把这两类分开写，否则报告会变成一份自我安慰。
