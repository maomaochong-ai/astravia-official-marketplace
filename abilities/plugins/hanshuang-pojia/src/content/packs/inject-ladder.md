# 注入层阶梯

三层，自下而上。层级越高，越不容易被当成「可驳回的偏好」，但代价也越大。

## 第 1 层：载荷块（`AGENTS.md` / `CLAUDE.md` / 规则文件）

- 形态：标记块包住的常驻指令，块外是用户自己的内容。
- 生效条件：宿主把项目说明按**数据**读取，且未启用「记忆优先」模式。
- 已知失效：模型把这段归类成「本机偏好」，然后点名驳回 —— 实测在 OpenCode 上稳定复现。
- 卸载：摘块即可，逐字节可还原。

## 第 2 层：系统层（`agent/<name>.md` 当成系统提示词）

- 形态：整份文件就是该 agent 的系统提示词，宿主不再注入内置模板。
- 生效条件：配置里把默认 agent 指向它（如 `default_agent`）。
- 为什么有效：提示词在**系统位置**，与被当作数据的项目说明不在同一个判断层。
- 代价：整份替换，会覆盖同名的自定义 agent 定义；必须先备份。
- 卸载：删文件 + 配置键还原成原值（原来没有这个键就删掉该键）。

## 第 3 层：配置层（配置键 / 云端记忆）

- 形态：改一个键，或通过目标进程改它自己的云端状态。
- 生效条件：键名与格式对得上目标版本；格式错会被静默忽略。
- 代价：改动最不可见，回滚依赖备份或目标的设置界面。
- 典型失败：目标重写自身命令行 → 调试端口不监听 → 通道建不起来。

## 选择顺序

1. 先看目标有没有系统层入口（有就优先，一次到位）。
2. 没有则用载荷块，并接受「可能被驳回」这个前提。
3. 只有前两条都不成立时才动配置层，且必须先备份。

## 诚实边界

层级是**解释**，不是权限。换了层不等于一定生效：模型层的拒答倾向来自训练，提示词改变不了它。
能改的只有「这段指令被放在哪一层」和「它有没有被当成可驳回的对象」。
