# dsh-workflow · 画布 → 计划提示词 → 模型执行

> 出处：`D:\open-source-projects\dsh-jailbreak-workflow`（DeepSeek Harness 插件，npm `@minglink/dsh-jailbreak-workflow`）。
> 本文只写它的**流水线方法论**。

## 它解决的是什么问题

把「一串有先后、有分支、有通过判据的步骤」从提示词里搬到画布上，编译成一份计划提示词，交给当前会话的模型执行。
插件里**没有执行引擎** —— 所有执行都由会话中的模型完成，插件只负责把流程画出来、编译出来、把产出写回文件。

## 「破甲制作」流水线（我们取的那一块）

| 阶段 | 输入 | 产出文件 | 通过判据 |
|---|---|---|---|
| 1 探针测试 | 目标模型 | `probes.md` | ≥ 20 条有明确结论，其中拒答 ≥ 5 |
| 2 拒答模式分析 | 第 1 阶段样本 | `analysis.md` | 每个触发面能指到具体样本 |
| 3 定制破甲词 | 触发面清单 | `words.md` | 正文里没有一句要求模型「破例」 |
| 4 API 验证 | 同批探针重放 | `verify.md` | 有可归因的提升，且有反例 |
| 5 三件套交付 | 前四阶段 | `words.md` / `manual.md` / `report.md` | manual 的每条建议都能在 verify 里找到依据 |

这套阶段划分的价值在于**每步都有可检验的产出**，而不是「让模型试试看」。

## 它的其他能力（供对照，不整合）

| 能力 | 说明 | 我们不整合的理由 |
|---|---|---|
| 画布编辑 | 拖拽步骤与连线，支持分支 / 循环 / 回退 | 需要画布宿主，插件侧没有承载体 |
| 运行状态 | 画布上实时显示每步进度 | 依赖执行引擎 |
| 版本管理 | 保存版本、对比差异 | 工作流本体的能力，我们没有工作流本体 |
| 导出成 Skill | 把一个版本编译成 `SKILL.md` | 我们的提示词包已经等价：正文 + 模式的组合 |
| 工作流记忆 | 把跑通的做法记成 skill | 实验性；我们的 `install-state.json` 只记安装事实 |

## 我们的整合映射

| dsh 的机制 | 我们落在哪 | 形态差异 |
|---|---|---|
| 五阶段流水线 | `src/content/packs/jailbreak-research.md` | 写成**可注入的清单**：每阶段含输入 / 动作 / 产出 / 通过判据 |
| 「没有执行引擎」的分工 | `inject_target` 的三条路由（R1/R2/R3） | 同一思路：插件不假装执行，只把执行交给有能力的层 |
| 产出写回文件 | `install-state.json` + 报告工具 | 只记录事实，不记录「尝试」 |

## 我们没搬的

- **画布与节点执行引擎**：DSH 插件本体，重复实现只会得到一个更差的版本。
- **`.wflite.zip` 工作流包格式**：没有画布就没有导入对象。
- **「破甲制作」的 200+ 探针原文**：探针的价值在于**针对目标模型定制**，复制一份静态清单等于把别人的
  结论当成自己的结论。我们取的是「怎么设计探针」，不是「探针是什么」。
