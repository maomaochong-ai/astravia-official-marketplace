# 四个参考实现 · 整合地图

这份参考集回答一个问题：**插件里每个「注入 / 提示词 / 还原」的决定，依据是哪儿来的。**

四个来源各带一块能力，但它们的宿主形态不同，能搬的与不能搬的差别很大。下面这张表是全集的入口，
每一行都能点到对应的一页。

| 参考 | 它是什么 | 我们取了什么 | 我们没取什么 |
|---|---|---|---|
| [hanshuang-mac](./hanshuang-mac.md) | Electron 壳 + 随包 pwsh + 9 个目标的注入脚本 | 目标矩阵、标记块、系统层注入、`install-state.json` 清单式还原 | 桌面壳本身 |
| [deva](./deva.md) | 完整桌面 Agent（角色 / 成员 / 定时任务 / 记忆 / IM） | 提示词四层分层、破甲 + 逆向的双能力角色设定 | 成员协作、调度、中继 |
| [dsh-workflow](./dsh-workflow.md) | DeepSeek Harness 的工作流插件（画布 → 计划提示词 → 模型执行） | 「破甲制作」五阶段流水线及其通过判据 | 画布与节点执行引擎 |
| [release-repo](./release-repo.md) | 便携版 zip 的分发仓库 | 「装完之后长什么样」的验收口径 | 146.3 MiB 的构建产物 |

## 一张图看清整合位置

```
宿主 Astravia（执行层）           插件 hanshuang-pojia（知识层 + 计划层）
─────────────────────           ──────────────────────────────────
对话 Agent 的 shell/fs  ───────▶ R2 交 Agent 执行
命令通道 pwsh/sh        ───────▶ R1 插件自己执行
保存对话框               ───────▶ R3 用户手工执行
                                        ▲
                               domain/inject/{targets,script,state,apply}
                                        ▲
                    content/packs/{执行内核,注入层阶梯,破甲流水线,红队角色}
```

三条路由共用同一份脚本，差别只在谁按下回车。

## 为什么这份参考集不搬第三方正文

参考实现的 README 与调研文档有它们自己的许可证与生命周期：上游改一版，抄进来的正文就会变成
「看起来是事实的旧结论」。所以这一组文档只写两样东西：

1. **能力清单**：它能做什么，用什么机制做的；
2. **整合映射**：我们取了哪一块，落在哪个文件，为什么这样落。

原始结论需要核对时，看每页顶部的「出处」一行，去上游仓库读最新版。
