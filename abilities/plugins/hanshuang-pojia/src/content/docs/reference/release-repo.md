# 发布仓库 · 「装完长什么样」的验收口径

> 出处：`D:\open-source-projects\hanshuang-pojia-release`（只放构建产物的分发仓库，zip 走 Git LFS）。

## 它是什么

一个纯分发仓库：`寒霜破甲.zip`（146.3 MiB）由 Git LFS 托管，README 写明校验方式
（`git lfs ls-files --long` 看 OID 与字节数、`certutil -hashfile` 比对 SHA-256）。
没有源码，没有脚本。

## 为什么仍然进这份参考集

因为它定义了一件事：**装完之后目录长什么样**。这是插件的验收口径 —— 我们的注入计划如果生成的文件
布局和用户以为的不一样，那「装成功」就是自说自话。

包内结构（上游定义）：

```
寒霜破甲.zip
├── 寒霜破甲工具.exe          # 主程序（Electron 便携版）
├── 卸载-便携版.bat           # 卸载脚本
├── resources/
│   ├── app.asar              # 应用主体
│   ├── install*.ps1          # 各工具链安装脚本
│   └── 寒霜v*.md             # 文档
├── locales/
└── *.dll / *.pak / *.bin     # Electron 运行时
```

两条使用条件，我们照抄进计划里：

1. 解压到**纯英文路径** —— 中文路径会导致启动异常；
2. 卸载走目录内的 bat，而不是手删。

## 我们的整合映射

| 上游约定 | 我们落在哪 |
|---|---|
| 标记块包住的注入、可摘除 | `INJECT_MARKER_BEGIN/END`，与上游注入器互认 |
| 「先备份再追加、绝不吞掉用户内容」 | `script.ts`：第一步永远是带时间戳的备份；`marker-block` 只替换块内 |
| 卸载按清单精确回收 | `state.ts` 的 `removalInstructions()`，只列装过的路径 |
| 纯英文路径 | 当前不落地主目录的路径由目标决定；脚本不生成中文目录名 |

## 我们没搬的

- **zip 本体**：发布产物进不了插件包，也不该进。插件包是代码与语料，不是安装器。
- **Git LFS 流程**：那是分发仓库的发布节奏，与插件无关。
