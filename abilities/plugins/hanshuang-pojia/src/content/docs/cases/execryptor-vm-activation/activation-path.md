# 激活路径与补丁闭环：状态码、stub、副作用与两条入口

> 配套：`cases/execryptor-vm-activation/reverse-engineering`（画像、通道、否证）
> 地址为教学值（ImageBase `0x140000000`），实际复现以现场重新定位为准。
> 端点已占位，样本哈希与证书主体不在本仓库。

---

## 一、状态码与两条入口

主程序通过共享内存向授权运行时请求，运行时回复结构化文本，其中 `result` 是三态之一：

| `result` | 语义 | 主程序处理 |
| :--- | :--- | :--- |
| `0` | 失败 | 写失败状态，弹 `msgRegFailed` |
| `2` | 过期 | 写有效期，走失败路径 |
| `3` | 成功 | 写 `RN` / `RC`，归一类 `LicType`，进入已注册态 |

只有 `3` 会落到写注册表那一段。

两条**互不相同**的入口，都必须验证：

```
交互式激活   CLicenseManager::Activate          0x1400320D4
  └ VerifySerialNumberW                          0x140009E60
      └ ExecuteXMLRequest                        FUN_140009290   （共享内存 + 事件）

启动检查     CLicenseManager::CheckRegistration  0x1400329C4
  └ IsRegistered 封装                            FUN_140009db0
      └ 同一通道（状态查询）
      └ 末尾 FUN_140009270 拉起 Helper，失败 TerminateProcess
```

第二个入口的存在决定了"只修第一条等于没修"。

## 二、补丁点

```asm
; 原始
0x140009E0F  E8 B4 4A 2D 00   call 0x1402DE8C8      ; 从已解析的文档里取整数
; 补丁
0x140009E0F  E8 0E 78 F9 FF   call 0x140001622      ; → 自建 stub
```

```asm
; stub：位于 .text 尾部连续 CC 填充区（0x140001622 起）
0x140001622  B8 03 00 00 00   mov eax, 3
0x140001627  C3               ret
```

| 项 | 值 |
| :--- | :--- |
| 补丁字节数 | 5（`call rel32` 只改位移，操作码不变） |
| stub 字节数 | 7 |
| 原始字节 | `E8 B4 4A 2D 00` |
| 补丁字节 | `E8 0E 78 F9 FF` |
| stub 字节 | `B8 03 00 00 00 C3` |
| 栈影响 | 无（stub 不 push/pop） |
| 返回寄存器 | `eax`（与被替换的调用一致） |

位移换算：`0x140001622 − (0x140009E0F + 5) = −0x87F2` → 小端 `0E 78 F9 FF`。
这段算术值得当场验一遍，它是"补丁字节正确性"的唯一客观依据。

### 为什么不是别的改法

| 改法 | 结果 |
| :--- | :--- |
| 改后面的比较 | 可行，但值的来源仍在多处被消费，一致性靠人维护 |
| 改通用"取整数"辅助函数 `0x1402DE8C8` | **不可行**：多调用点共用，无关读取全部返回 3 |
| 整个函数 `ret` | 调用方期待结构被填充，跳过 → 未初始化字段 → 后续分支异常 |
| 禁用 Helper | 它是启动检查的一部分，缺失即 `TerminateProcess` |
| 逆向 VM | 无界投入；且不必要 |

## 三、注册表侧：值名与归一

成功分支写入：

| 值名 | 内容 | 来源 |
| :--- | :--- | :--- |
| `RN` | 注册名 | 响应字段（内存 `param_1+0x170`） |
| `RC` | 序列号 | 响应字段（内存 `param_1+0x178`） |

键路径：`HKCU\Software\项目E Software\项目E`。

`LicType` 存于 `param_1+0x188`，值 `0` 会归一到 `1`（单机授权）。
归一发生在 `local_478` 处的结构清零（`memset(0, 0x16)`）之后 —— 顺序很重要：

```
清零结构 → 写 result 相关字段 → 归一类 LicType → 返回
```

若只改状态而不让调用方走到"写字段"，`LicType` 保持清零后的 0，后续 UI 与功能门会读到未授权。

值名短且不具语义（`RN` / `RC` / `VH` / `VL` / `RF` / `RL`），属于"用混淆代替保护"：
可静态枚举，也可在运行时按字符串引用定位。

## 四、legacy 通道与试用分支

启动检查在 `RN` / `RC` 为空时走另一条：

```
SecureReadW(key = "RegName" / "SerialNum")   ← legacy 通道
  有值 → 视作已注册
  无值 → 试用 30 天（0x1e）
```

试用期带时钟防护，字符串常量可作定位锚：

| 常量 | 含义 |
| :--- | :--- |
| `CLCK MVD BCK` | 检测到时钟被回拨 |
| `CLCK DS LT {}` | 当前时间早于记录时间（格式化模板） |
| `_atoi64` | 时间戳解析 |

这解释了一个常见误判：把系统时间调回去并不会延长试用，反而触发另一条提示。

## 五、副作用矩阵（验收用）

| 面 | 读什么 | 补丁后表现 | 处置 |
| :--- | :--- | :--- | :--- |
| 注册对话框 | `result == 3` | 以成功关闭 | — |
| 启动检查 | `RN` / `RC` | 未写则显示未注册 | 手动写入两项 |
| 关于 / 注册信息 | 显示名（响应字段） | **空** | 正常现象，写 `RN` 即可 |
| 授权类型 | 归一后的 `LicType` | 单机授权 | 依赖清零-写入顺序 |
| 便携版逻辑 | `LicType` 998 / 999 | 不适用 | 另一条通道（`license.dat`） |
| 联网 | `<AUTH-SRV>/verify.php` | 仍会尝试 | 用 hosts 屏蔽即可，不影响判定 |

### 为什么"空名字"是正常现象

补丁重定向的是**状态解析**，不是响应内容。主程序从未拿到名字，于是显示为空。
想让显示也正确，就自己写 `RN`；想让功能门打开，状态已足够。
把这两件事混在一起，会导致"看起来没生效"的误判。

## 六、验证清单

| 检查 | 期望 | 说明 |
| :--- | :--- | :--- |
| `0x140009E0F` 回读 | `E8 0E 78 F9 FF` | 补丁已落 |
| `0x140001622` 回读 | `B8 03 00 00 00 C3` | stub 已落 |
| stub 后填充 | 仍为 `CC` | 未覆盖相邻函数 |
| 交互式激活（非法序列号） | 成功关闭 | 行为验证 |
| 写 `RN` / `RC` 后重启 | 显示已注册 | 第二条入口验证 |
| Helper 进程 | 仍在 | 未被禁用 |
| 磁盘哈希 | 改副本则仅两处变化；改内存则原文件不变 | 完整性 |

补丁器自带 `--verify` 输出 `is_patched=True`，C# 测试工具跑断言全集得 ALL PASS。
两者证明"位置与字节正确"，**不证明"行为正确"** —— 行为要看上表第 4、5 行。

## 七、环境与操作坑

| 坑 | 现象 | 处置 |
| :--- | :--- | :--- |
| 目标单独放在临时目录 | 启动即失败 | 必须与 Helper、`languages\*.xml` 同目录 |
| 脚本启动 GUI 子进程 | 命令结束后目标被连带终止 | 整个"启动→等待→枚举"放在同一条命令内 |
| 大函数默认截断 | 反编译输出被截到 5,000 字符，看起来"函数很短" | 显式放大导出上限 |
| 直接改通用辅助函数 | 无关整数全部变 3，多处界面异常 | 只改调用点 |
| 只改交互式路径 | 下次启动回到未注册 | 同时处理启动检查的输入（写 `RN` / `RC`） |

## 八、残余风险

| 项 | 状态 |
| :--- | :--- |
| 服务端推低有效期 | `[unverified]` 若运行时后续返回 `2`，状态解析再次被覆盖为 2 —— 因为补丁钉的是"这一次解析" |
| 多语言资源差异 | `[unverified]` 仅验证一种语言包下的界面路径 |
| 便携版 | `[observed]` 不适用（另一条通道） |
| 新版本偏移 | `[unverified]` 只要重编译，`0x140009E0F` 与 `0x140001622` 都需重新定位 |

第一条是这类补丁的固有限制，也正好是整改建议的落点：**状态必须以不可伪造的凭据传递**，
否则任何一次"解析 → 整数"的转换都是可替换的接缝。
