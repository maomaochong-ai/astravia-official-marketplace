## 三、四段关键反汇编

### 3.1 授权分支（位点 1）

```asm
call dword ptr [<iat 授权状态查询>]
85 C0              test eax, eax          ; ← 补丁 85 → 33
0F 85 1B 01 00 00  jne  <失败路径>
C6 85 4F F5 FF FF 01   mov byte ptr [ebp-0xAB1], 1   ; 恒置「已授权」
```

`test eax,eax` 改成 `xor eax,eax` 之后：`eax = 0`、`ZF = 1`、`jne` 永不跳转，
`[ebp-0xAB1]` 被无条件置 1。一个字节，不动调用、不动返回值。

### 3.2 试用期计算（位点 2）

```asm
A1 DC 9C 77 00     mov eax, dword ptr [0x779CDC]   ; 读「试用状态标志」
F7 D8              neg eax
1B C0              sbb eax, eax                    ; 0 → 0x00000000；非 0 → 0xFFFFFFFF
83 E0 0F           and eax, 0xF                    ; ← 补丁起点
83 C0 0F           add eax, 0xF                    ; ← 补丁终点
A3 E0 9C 77 00     mov dword ptr [0x779CE0], eax   ; 写「试用天数常量」
```

| 标志 | 原逻辑 | 结果 |
| :--- | :--- | :--- |
| 0 | `0 & 0xF + 0xF` | **15 天** |
| 非 0 | `0xFFFFFFFF & 0xF + 0xF` | **30 天** |

补丁 `83 E0 0F 83 C0 0F` → `B8 FF FF FF 7F 90`（`mov eax,0x7FFFFFFF` + `nop`），
写入值恒为 `2147483647`。

**地址换算印证**：`[0x779CDC]` → RVA `0x379CDC` → 文件偏移 `0x378CDC`；
`[0x779CE0]` → RVA `0x379CE0` → `0x378CE0`。公式：
`文件偏移 = 节区 RawPtr + (VA − ImageBase − 节区 VA)` = `0x378000 + (0x379CDC − 0x400000 − 0x379000)`
= **`0x378CDC`**，与第 14 行数据位点完全咬合。换算对不上表时，三个输入里必有一个错。

### 3.3 SEH 型守护线程（位点 4–8、10）

```asm
6A FF              push -1                ; ← 补丁点：6A → C3 (ret)
68 <SEH 作用域表>  push <scope table>
64 A1 00 00 00 00  mov eax, fs:[0]
50                 push eax
81 EC 64 01 00 00  sub esp, 0x164
```

函数体大小可作辅助判据：守护线程 A/C 是 `sub esp,0x164`，B 是 `0x64`，D 与看门狗关联函数是
`0x1C4`，E 是非 SEH 型（`push ebp / mov ebp,esp / and esp,-8`）。

⚠️ **COMDAT 折叠**：守护线程 D 与看门狗关联函数前 24 字节逐字节相同、共享同一 SEH 作用域表。
这两个位点的特征码**不能从函数序言起步**，只能向前锚定到前一个函数的尾部。

### 3.4 注册对话框对抗链（位点 15，b11.3 新增）

```asm
0048E265  FF 15 04 40 69 00   call RegQueryValueExA
0048E26B  85 C0               test eax, eax
0048E26D  74 0C               je   0x48e27b        ; ← 补丁点：74 → EB
0048E26F  8B CB               mov  ecx, ebx
0048E271  E8 AA B3 FF FF      call 0x489620       ; 弹注册对话框（资源 138）
0048E276  E9 BD 00 00 00      jmp  0x48e338
0048E27B  89 7D DC            mov [ebp-0x24], edi  ; 已注册路径，继续
```

触发链：先 `RegOpenKeyExA(HKCU, "SOFTWARE\项目D")`，键不存在时回退到全局句柄
`HKCU\Software\项目D`；两次 `RegQueryValueExA(..., "Serial")` 都失败才弹框。

补丁 `74` → `EB`：永远走「序列号已存在」路径，跳过弹框且不改变后续逻辑。

### 3.5 位点 15 为什么必须是可选的

b10 / b11.2 的同一位置是**句柄清理路径**（`test esi,esi / cmp / RegCloseKey`），
布局完全不同，特征码在那两版上**零命中**。若强行要求命中，引擎会在 b10 / b11.2 上拒绝写补丁。
因此引入「可选位点」语义：

```
必需位点全部命中 → 放行写入
可选位点未命中   → 打印「跳过可选位点（本版本无此逻辑）」，不阻断
```

可选位点的双态特征码（原始 / 补丁态）：

| 项 | 值 |
| :--- | :--- |
| 原始态 | `8B0DE86C780051FF150440690085C0740C` |
| 补丁态 | `8B0DE86C780051FF150440690085C0EB0C` |
| 补丁偏移 | 15（相对特征码起点） |
| 命中范围 | 仅 b11.3 及以后 |

## 四、数据段位点：合并、漂移与精确锚定

### 4.1 合并

```
原值: 01 00 00 00 | 1E 00 00 00     (标志 = 1, 天数 = 30)
补丁: 00 00 00 00 | FF FF FF 7F     (标志 = 0, 天数 = 0x7FFFFFFF)
```

两点相距仅 4 字节，**必须合并为单条 8 字节条目**：若拆成两条，各自 6 字节的特征码互相包含，
两条都不唯一，且打了第一条之后第二条就再也不会命中。

### 4.2 漂移

b15.3 中该常量块前方多出 2 个零填充字节，位点从 `0x378EDC` 移到 **`0x379524`**。

朴素滑动汉明距离在此给出**错 2 字节**的位置（`0x379546`），距离仅 2 —— 看起来完美。
修正流程：模糊候选 → 期望字节精确匹配 → 精确锚点搜索（`AVCDownloadComponents` 字符串 + 常量对）
→ capstone 语义对照。**四项全过才算定位成功。**

## 五、AOB 特征码的生成与验证

### 5.1 生成规则

1. 对每个位点，在**全部支持的版本**上取共同字节区（交集）；
2. 同时要求原始态与补丁态各自在对应文件里**唯一命中 1 次**；
3. 相邻 ≤ 4 字节的位点合并；
4. 遇到 COMDAT 折叠，向前锚定到前一函数尾部，接受短特征码（实测最短 14 字节）；
5. 位移量不同的字节用 `??` 掩码而非裁掉，保持窗口长度固定、唯一性计数可比。

### 5.2 实测规模

| 指标 | 值 |
| :--- | :--- |
| 位点数 | 14（可选位点单独计） |
| 特征码总字节 | 755 |
| 平均 | 53.9 B/点 |
| 最短 | 14 B（看门狗关联函数，锚定型） |
| 最长 | 118 B（授权分支检测，三版本交集） |

### 5.3 扩到五版本后的收窄

| 位点 | 三版本 | 五版本 |
| :--- | :--- | :--- |
| 授权分支检测 | 118 B | 24 B |
| 守护线程 F | 80 B | 29 B |
| 试用期最大值 | 90 B | 13 B |
| 合计 | ~1,050 B | 378 B |

13 字节仍然唯一 —— 唯一性看的是命中数，不是长度。

## 六、PE 门禁与产物基准

### 6.1 门禁

```
MZ 校验 → PE 签名校验 → 节区边界校验 → RawPtr+RawSize ≤ 文件长度
e_lfanew = DWORD@0x3C ; COFF = e_lfanew+4 ; Optional = COFF+20
CheckSum        = Optional+0x40
DataDirectory[4]= Optional+0x60 (PE32) / 0x70 (PE32+)
ImageEnd        = max(RawPtr+RawSize)
```

### 6.2 校验和

| 文件 | 存储值 | 标准算法 | 结论 |
| :--- | :--- | :--- | :--- |
| 官方 b10 | `0x005ECD00` | `0x005ECD00` | ✅ 吻合 |
| 官方 b11.2 | `0x005EF1D7` | `0x005EF1D7` | ✅ 吻合 |
| 官方 b11.3 | `0x005E9C44` | `0x005E9C44` | ✅ 吻合 |
| 上一代工具产物 | `0x005F0BEA` | `0x005EBDA3` | ❌ 无法复现（穷举 4×16 变体） |

结论：写入无效值仍可运行 ⇒ 目标与系统均不校验该字段 `[observed]`；但仍应重算以保证文件自洽。

### 6.3 产物基准（五版本）

| 版本 | 生效位点 | 修补后体积 | 修补后校验和 |
| :--- | :--- | :--- | :--- |
| b10 | 14/15（可选跳过） | 6,189,056 | `0x005EBDA3` |
| b11.2 | 14/15（可选跳过） | 6,189,568 | `0x005E84FA` |
| b11.3 | 15/15 | 6,189,568 | `0x005EC25E` |
| b12.3 | 15/15 | 6,189,568 | `0x005F6E1F` |
| b15.3 | 16/16 | 6,191,104 | `0x005F3D7B` |

**零回归确认**：b10 / b11.2 / b11.3 的产物 SHA-256 与上一代引擎逐字节一致 ——
扩版本没有改动既有产物。回归测试 89 项断言全绿：五版本端到端、幂等性、差异字节白名单、
陈旧备份刷新、还原守卫，以及负向用例（节区截断 / 特征码不符 / 空文件 / 非 PE → 全部拒绝且零写入）。

## 七、回滚

| 场景 | 动作 |
| :--- | :--- |
| 写入中途失败 | 从 `.rollback.tmp` 恢复原文件（写入前已复制） |
| 产物复读解析失败 | 同上，并删除临时文件 |
| 差异字节超出白名单 | 回滚并报出越界偏移列表 |
| 用户主动还原 | 用版本匹配的 `项目D.exe.BAK`（版本不匹配时守卫拒绝） |

原始文件在整条链路里从未被覆盖：所有写入都发生在临时文件上，校验通过后才替换。
这条设计的直接价值是——**实验失败不会毁掉样本**，而样本往往只有一份。
