# 项目I —— 授权算法原理：CNG blob、请求串、滑窗验签与试用时钟

> 目标组件：`项目IX64.dll` / `项目IA64.dll`（同源逻辑）· 验签经 BCrypt（CNG）完成
> 脱敏：`CONST` 字面值已移除，模数只保留截断形式，样本哈希置为 `<实测哈希>`；布局、偏移、字段与算法结构保留。

---

## 一、密钥容器

组件内嵌的是 **CNG 公钥 blob**，不是 CryptoAPI 的 `RSA1` blob —— 两者的字段顺序不同，
读错会把"指数 + 模数前半段"当成模数：

| 偏移 | 长度 | 字段 | 本样本值 |
| :--- | :--- | :--- | :--- |
| `+0x00` | 4 | 魔数 | `RSA1` |
| `+0x04` | 4 | 位长 | 1016 |
| `+0x08` | 4 | `cbPublicExp` | 3 |
| `+0x0C` | 4 | `cbModulus` | 128 |
| `+0x10` | 4 | `cbPrime1` | 0 |
| `+0x14` | 4 | `cbPrime2` | 0 |
| `+0x18` | 3 | 指数 | `01 00 01`（`e = 0x10001`） |
| `+0x1B` | 128 | 模数 | `c3a6cca1…63ce79`（截断展示） |

| 项 | 值 |
| :--- | :--- |
| x64 组件内偏移 | 文件 `0xA3160` |
| arm64 组件内偏移 | 文件 `0xB1FB0` |
| 小因子 | 2663（试除命中） |
| 剩余余因子 | ~1005 bit |

`rz-find -s "RSA1"` 一次定位；换版本时用「魔数 + 合理的位长字段」两个条件复核，不要照抄偏移。

**关键判断**：`n = 2663 × (1005 bit 质数)`。小因子好找，大余因子不可分解 ——
"模数偏小"是个应当写进报告的合规问题（低于当前建议强度），但它**不**构成可用的伪造路径。
这两件事在报告里必须分开陈述。

## 二、请求串

```
R = LicenseHash + md5hex(A) + md5hex(B)        → 96 个 hex 字符
  LicenseHash : 注册表里存的 md5hex(user key)，32 字符
  A           : 机器码 #1（SMBIOS 串，含回退源），按 word 交换处理
  B           : 机器码 #2（`'RSMB'` Type-1 UUID 形态）
  md5hex(x)   : BCryptHash(MD5) → `%02x` × 16，小写
```

三个实现细节：

- `LicenseHash` 有迁移逻辑：注册表默认值长度 > `0x1e` 时被替换为 `md5hex(现值)`，
  所以两种历史形态都可能存在于现场，生成端必须都接受。
- A/B 取不到时回退到固定占位串（归档中为 `xxxx xxxx` / `yyyy yyyy`）。
  这解释了为什么"没有 SMBIOS 权限的机器"上算出的 `R` 也能被接受 —— 客户端也用同一个回退。
- 同一串 96 hex 也会发给激活接口。因此**抓一次激活请求就得到现成的 `R`**，
  比先推导再比对省整整一轮排查。

`md5hex` 的实现本身也有坑：`BCryptHash(MD5)` 之后按 `%02x` 逐字节格式化，
若误用大写或补零不足，长度仍可能是 32 但内容不同 —— 用一个已知输入对一次即可确认。

## 三、激活数据与签名载荷

```
P = R[0:32] + (CONST | R[32:96]) + "SABALL" + pad(0x00)     → 128 字节
P[0:32]   = LicenseHash
P[32:96]  = CONST（64 hex 字符）        ← 字面值已移除
   或     = md5hex(A) + md5hex(B)       ← 另一种被接受的形态
P[96:102] = "SABALL"
P[102:128]= 0x00 填充

sig = P^d mod n
ActivationData = base64(sig)  →  注册表 REG_BINARY
```

`CONST` 位于 `.rdata` VA `0x1800A3E90`，长度 64 字符。它参与签名的载荷，作用等同于盐值，
因此本仓库只保留**位置、长度与在模板中的偏移**，不保留字面值 —— 有这三项足以在现场重新定位。
`SABALL` 在机器码里表现为立即数 `0x41424153` / `0x4C4C`（小端），
这也是在反汇编里搜尾部标记时最有用的形态。

注意 `P` 里两种中间字段形态是**并列可接受**的：`CONST` 型与「A/B 双哈希」型。
这既解释了为什么旧版生成的激活数据仍然有效，也说明生产者只需实现其中一种。

## 四、验签（`Ordinal_102`）

```
block = base64decode(ActivationData)^e mod n       # BCryptImportKeyPair + BCryptEncrypt
for o in 0 .. 0x1b:                                 # 28 个偏移，步长 1
    block[o   : o+32 ] == LicenseHash
and (
      block[o+32: o+96 ] == CONST
   or block[o+32: o+64 ] == md5hex(A) and block[o+64: o+96] == md5hex(B)
)
and block[o+96: o+102] == "SABALL"
→ 已激活：返回 1，且 out[0] = '1'
```

三个必须记住的读法：

1. **滑窗**。不是等值比较，是 28 个起点逐个试。所以"偏移 0 不匹配"什么都不能说明。
2. **一个大缓冲区**。反编译输出会把它拆成 `local_b8` / `local_98` / `local_78` / `iStack_58` /
   `asStack_54` 等一堆局部变量 —— 先认出它们是同一块 128 字节，再解释字节区间。
3. **两种中间形态是 or**。写成 and 会导致"自己生成的激活数据在旧版客户端上失败"。

验签之后还要过一次状态判定（试用/正式），但验签通过本身就已经决定"是否已激活"。

## 五、试用时钟

```
首装时间戳 = 注册表键的最后写入时间
             键路径 HKCU\...\Explorer\CLSID\{ md5hex("<产品名>" + "<分组>") - 1 - 31 - 9 }
试用期     = 100 天
跳过过期判定 if now < 首装时间戳        （容忍时钟回拨）
           or year(now) >= 2028          （硬编码期限）
```

两个由设计产生的效果：

- 时间戳锚在"键的最后写入时间"上，可写即可能被改写，回拨时钟也能延长；
- 2028 是硬编码常量，到那一年之后所有机器的过期判定都会跳过。

第二点属于工程债而非漏洞：它保证了产品在某个日期之后集体失效授权管控，
且厂商收不到任何信号。整改建议里应当列在最前面之一。

## 六、导出与入口

| 序数 | 作用 |
| :--- | :--- |
| `Ordinal_100` / `Ordinal_101` | 试用期判定（写结果到输出参数） |
| `Ordinal_102` | **验签入口**，返回 1 = 已激活，同时写 `out[0]='1'` |
| `Ordinal_103` | 组装请求串（`lstrcpy` / `lstrcat` 三段拼接） |

三个都是无名导出。这对补丁有利：没有名字的导出不会因为版本升级而改名，入口相对稳定；
对分析稍麻烦：只能靠字符串与调用关系定位。

补丁落在 `Ordinal_102`，保留 `out[0]='1'` 的写入 —— 上层会读这个字节，
只改返回值不改状态字节，会出现"函数说激活了但界面仍是试用"的分裂状态。

## 七、可行性结论

| 路线 | 状态 |
| :--- | :--- |
| user key 自带本地自洽校验段 | **不存在**（对照同族产品的 19 字符校验串） |
| 用内嵌公钥伪造激活数据 | 不可行（缺私钥指数） |
| 分解模数 | 1016 bit，小因子 2663，余因子 ~1005 bit **不可分解** |
| 由他机激活数据复用 | 需私钥 |
| **本地要素复现 + `Ordinal_102` 补丁** | **可行**，验收以直调导出为准 |

这张表就是本案例的产出：四条否定 + 一条可行。它的价值不在于"最后成功了一条"，
而在于**前四条各自都有具体证据**，因此"再试一次算号"这种返工不会再发生。

## 八、限制与未验证项

| 项 | 状态 |
| :--- | :--- |
| `CONST` 在其他版本中的位置与长度稳定性 | `[inferred]` 同源逻辑推断位置稳定，未逐版本比对 |
| arm64 组件与 x64 的算法一致性 | `[unverified]` 仅确认公钥 blob 另有一份 |
| 模数是否存在比 2663 更大的可利用因子 | `[unverified]` 未做长时 ECM/P-1 |
| 在线激活接口的返回结构与是否另有校验 | `[unverified]` 未抓包 |
| 试用时间戳键的修改在权限受限账户下的可行性 | `[unverified]` 未测低权限场景 |
| 补丁在配置器（`项目ICfg.exe`）路径上的等效性 | `[unverified]` 本案例只覆盖主组件 |
