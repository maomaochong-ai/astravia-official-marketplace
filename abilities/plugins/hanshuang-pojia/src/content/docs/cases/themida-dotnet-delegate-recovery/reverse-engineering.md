# Themida 加固的 .NET 客户端：四层对抗与单字段判据

> 案件：某 Windows 桌面文件管理器（下称「项目K」）v7.19，.NET Framework 4.7.2 / WPF / x64。
> 授权模型为 30 天试用 → 会员（计时 / 永久）。
> 样本哈希 `<实测哈希>`。本文保留偏移、计数与结构常量，密钥与盐值已按脱敏规范移除。

## 结论先说

`项目K` 的客户端鉴权可稳定复现旁路，根因不在那四层壳，而在壳下面一行普通的托管代码：一个
`public static int Days` 字段单独决定全部权益分支。四层防护把「读懂它」的成本抬得很高，却没有改变
「谁说了算」——依然是客户端自己。

定级：

- **CWE-602** 客户端强行实施服务端安全机制：授权有效性由本地整型单点决策，核心权益无服务端权威闭环。
- **CWE-321 / 327** 硬编码 / 可推导密钥：许可密文的 Key 与 IV 全部由本地机器码切片得到，无任何服务端
  秘密参与，算法为 AES-128-CBC。
- **CWE-345** 缺少真实性与完整性校验：载荷无签名、无 MAC；「双存储一致性比对」把同一份密文写两处即可
  绕过。
- **CWE-472** 外部可控数据未校验：到期日期是明文字段，客户端直接解析成整数算剩余天数。

## 一、四层防护各自的真实作用

| # | 层 | 观测到的特征 | 实际保护的东西 |
|---|---|---|---|
| 1 | Themida / WinLicense 原生壳 | `.themida` + `.boot` 节；导入表只剩 `kernel32!GetModuleHandleA`；`IMAGE_DIRECTORY_ENTRY_COM_DESCRIPTOR` 被清零 | 磁盘形态，不保护运行期 |
| 2 | 方法体虚拟化 | 13983 个 `MethodDef` 中 7860 个被替换为 4 字节桩（`nop;nop;ldnull;ret`） | 一切从文件读方法体的工具 |
| 3 | 字符串加密 + 委托跳板 | 全部 `ldstr` 只剩 35 条明文，且 35 条全是壳自身的字符串 | 应用的「文字」——标签、提示、值得一看的名字 |
| 4 | 运行期加载的授权核心 | `SpeedImage..cctor` 经 `Assembly.Load(byte[])` 载入内嵌程序集（程序集名 `1kznju2l`） | 静态分析的视野 |

### 1.1 为什么「内存重建」比「脱壳」省事

壳必须把托管模块交给 CLR，否则产品无法运行——这是它唯一可用的执行路径。所以进程里一定存在 COR20 头
（本案位于 RVA `0x2000`），无论文件里那一项是否被清零。路线因此确定为「重建模块」，而不是「分析原生
代码」。

代价也要先讲清：被保护节区的 `rawsize` 为 0，磁盘上那些「指令」在加载后会被覆盖，任何静态补丁改的
都是不存在的字节。整个案件过程中磁盘文件保持逐字节不变。

### 1.2 JIT vtable：唯一的收窄点

方法体虚拟化并不自己解释 IL，它把解密后的方法体在编译期交给 JIT。也就是说壳要么成为
`compileMethod`，要么替换它——只有一个入口。

判断壳是否已经在路上：读 `ICorJitCompiler` vtable 的第一项，与 `clrjit.dll` 的模块基址相减。若结果为负
或远超模块范围，说明壳已挂钩（本案实测如此）。在同一个槽位上挂第二层，转发原函数，即可截获真实 IL。

截获到的东西有两个坑，必须先知道：

- 传进来的 `ILCode` 是**裸 IL**，不含方法体头；
- `EHcount` 恒为 0，即使原方法有异常处理器。

因此 `maxStack`、`localVarSigTok` 与异常子句必须回磁盘桩头里取。用默认值重建，等于静默丢掉所有
`try/catch`——本案实测踩过一次，症状是「反编译出来的代码少了一层错误处理，逻辑看起来荒谬」。

### 1.3 回填与反编译

按行大小 18 解析 `MethodDef` 表（RVA 在行首 4 字节），用截获的 IL 重建 fat 头方法体，写入壳预留的
scratch 区（`0xA00000+`），回写 RVA 列并扩展 section 覆盖 scratch。之后一次反编译即可拿到 1163 个文件的
真实 C# 源码，`[observed]`。

### 1.4 委托跳板是纸老虎

字符串解密与调用转发都靠静态委托字段。运行期反射枚举全部静态字段，读 `Target`/`Method` 即得完整映射：
**858 个委托字段**全部解析，`[observed]`。对照另一个数字才有说服力——明文 `ldstr` 只剩 35 条。858 比 35，
这个比例本身就是发现。

### 1.5 别对着外层模块写报告

授权核心经 `Assembly.Load(byte[])` 载入，磁盘上没有对应文件。枚举 `AppDomain` 已加载程序集，取「名字
对不上任何文件」的那个 dump 出来单独反编译（728 行 C#），`[observed]`。跳过这一步的后果很具体：报告
写得很漂亮，但一次都没看到决定用户是否付费的那段代码。

## 二、授权架构：机器码、载荷、加密

机器码（本案称 JQM）由三项本机事实加一个盐值算得：

```
JQM = MD5_HEX( 主板序列号 + <REDACTED-SALT-19CH> + CPU ProcessorID + 语言后缀 )  → 每 4 字符插入 '-'
```

主板来自 `Win32_BaseBoard.SerialNumber`，CPU 来自 `Win32_Processor.ProcessorID`；语言后缀在 `zh` 下为空，
其它语言为 `-<大写语言码>`。**盐值是一个 19 字符的硬编码常量**，属商业授权机密，按脱敏规范整条删除，
本文只保留它的长度与作用，`[observed]`。

许可载荷是一行制表符分隔的文本：

```
<JQM> \t <到期日期 yyyy-MM-dd> [\t <邮箱>]
```

加密为 `RijndaelManaged` / **AES-128-CBC / PKCS7 / UTF8**。Key 与 IV 从 JQM 去横线后的 32 字符按固定切片
拼装：

| 切片 | 下标区间 | 长度 |
|---|---|---|
| a | `[0,1)` | 1 |
| b | `[1,7)` | 6 |
| c | `[7,14)` | 7 |
| d | `[14,16)` | 2 |
| e | `[16,20)` | 4 |
| f | `[20,23)` | 3 |
| g | `[23,27)` | 4 |
| h | `[27,32)` | 5 |

```
AES Key = f + g + h + e   // 16 字节
AES IV  = a + c + d + b   // 16 字节
```

关键缺陷在这里：**密钥材料 100% 来自客户端本地可推导的信息**，没有任何服务端秘密参与；载荷无签名、
无 MAC。这意味着任何一个能在本机复算机器码的人，都能自行构造一份「合法」密文，`[inferred]`（由算法
结构直接推出，本案另以实际构造验证，见下）。

### 2.1 双存储是伪防篡改

两处存储：注册表 `HKCU\SOFTWARE\Microsoft\<JQM 去横线去数字后前 3 字母>` 的值 `Configuration`，以及隐藏
文件 `%APPDATA%\Microsoft\Crypto\Keys\<JQM 去横线小写>`。文件被置 `Hidden`，创建/写入/访问时间被伪造成
与 `%APPDATA%` 目录创建时间一致。

读取时的唯一校验是「注册表密文 == 文件密文」。两者一致即放行——所以同时写入两处就绕过了全部防篡改
设计，`[observed]`。

### 2.2 单字段状态机

`项目K.App` 里的 `public static int Days`（默认 `-36500`）是唯一全局判据：

| 条件 | 状态 | 界面表现 |
|---|---|---|
| `Days >= 29200` | 永久授权版 | `PermanentLabel` 显示「永久授权版」，购买入口隐藏 |
| `0 < Days < 29200` | 计时授权 | 「您还有 X 天授权使用期」 |
| `Days <= 0` | 免费版 | 「免费使用版（全功能）」+ 催购弹窗 |

`29200 天 = 80 年`被当作「永久」阈值——这是 UI 约定，不是安全边界，`[inferred]`。

值得注意的是权益差异是**荣誉制**：过期后功能并不阉割，全部文件管理能力仍在，差别只有关于窗口的状态
文案、「购买会员」按钮是否 Collapsed、菜单栏购买/续费入口（`Days > 10` 时隐藏）以及启动时的到期提醒
弹窗。这一点影响报告写法：漏洞的实际危害是「授权状态与商业转化被旁路」，不是「未授权用户获得额外
功能」。

### 2.3 激活协议

服务端 `https://<AUTH-SRV>`，经系统代理发起 HTTPS `CONNECT`。`Controller.CheckRegistration(email)` 走
HTTP POST，超时 10000 ms，响应按 `\t` 分割，`array.Length >= 7` 时取 `array[6]` 作为注册码；
`Controller.FinishRegistration(window, 注册码)` → `App.SetGqm()` → 解密注册码
（`<x>\t<JQM>\t<到期日期|Invalid>\t<邮箱>`）→ 落盘。

## 三、云控复核：为什么「伪造成功」只维持一分半

原厂在启动约 15 秒后发起在线复核。若服务端判定未注册，客户端通过 `App.SetGqm()` 把本地许可覆写成
`<JQM>\tInvalid\t<邮箱>`，随后落盘毒化并 `Environment.Exit(0)`。实测：只伪造许可时，永久授权状态大约
维持 1~2 分钟，然后进程自行退出，`[observed]`。

这也是本类案件最容易写错的地方——「界面显示永久授权版」不是结论，只是两分钟内的一个瞬间。

### 3.1 托管层拦截的能力边界

实测该应用存在多条网络路径，托管层拦截只能覆盖一部分：

| 路径 | 实现方式 | 托管层是否可控 |
|---|---|---|
| 经 `WebRequest.DefaultWebProxy` | .NET 默认代理 | 可（`IWebProxy`） |
| 显式走系统代理 | `GetSystemWebProxy()` / 直接设 `request.Proxy` | 不可（绕过 `DefaultWebProxy`） |
| 自行解析域名后直连 IP | raw socket / 自建连接 | 不可（完全绕过代理层） |
| 自建 TLS 栈（`SslStream`） | 不经 `ServicePoint` | 不可（绕过证书回调） |

三层拦截（L1 默认代理、L2 证书校验回调 + 域名/解析 IP 黑名单、L3 `App.Days` 内存锁 + 许可看门狗）的
实测结果：直连服务器 IP 通道已截断，托管栈通道已截断，**自建 socket/TLS 通道未截断**——日志里 TLS 回调
一次都没触发，说明对方自己搭了 TLS 栈，`[observed]`。

结论要照实写：托管层拦截能**大幅削弱**云控，不能**完全截断**。真正彻底的切断必须下沉到 OS 层，让域名
解析直接返回 `127.0.0.1`（hosts 或防火墙），任何应用层代码都绕不过去。把「削弱」写成「阻断」是这类
报告常见的失真。

### 3.2 一次真实的设计事故：CLR 引导变量不能持久化

早期版本实现了 `SelfPersist()`，把 `APPDOMAIN_MANAGER_ASM` / `APPDOMAIN_MANAGER_TYPE` 写进
`HKCU\Environment` 并广播 `WM_SETTINGCHANGE`，想做到「只放一个 DLL，零配置生效」。

后果是灾难性的：这两个是 CLR 级引导变量，写进用户环境后，**此后启动的每一个 .NET 程序**（PowerShell、
资源管理器、第三方文件管理器、pythonw……）都会被强制加载该 DLL；那些进程目录里根本没有这个文件，于是
CLR 启动阶段直接失败：

```
System.IO.FileNotFoundException  →  System.TypeLoadException
   在 System.AppDomain.CreateAppDomainManager()
Starting the CLR failed with HRESULT 80131522   (COR_E_TYPELOAD)
```

表现是「窗口一闪而过」。实测影响 **82 个进程**，`[observed]`。

整改四条：删除 `SelfPersist()`（此后不再写任何全局环境变量）；新增 `IsTargetProcess()` 白名单守卫，仅当
`MainModule.FileName` 以目标程序名结尾时才动作；所有脚本对全局变量只读/只清；引导改为进程级启动器，
不落盘、不广播。

**铁律**：`APPDOMAIN_MANAGER_*`、`COR_PROFILER*`、`COR_ENABLE_PROFILING` 这类变量绝不可持久化。它们只能
走进程级通道，否则一次注入污染全机所有 .NET 程序。

排查方法论也可复用：某类程序集体「一闪而过」→ 查 `.NET Runtime` 事件日志里的 `TypeLoadException` +
`CreateAppDomainManager` → 关键线索是 `HRESULT 80131522` → 清掉 `APPDOMAIN_MANAGER_*` 后重测确认。注意
注册表清干净后，**已运行进程的环境块仍带毒**（尤其系统外壳），必须重启才能彻底恢复。

## 四、修复建议（纵深防御）

**服务端权威闭环**（最关键）：核心权益以服务端为唯一权威，客户端只缓存展示；在线复核结果以服务端签发
的短时效 token 下发，离线宽限期显式限定并强制降级；建立「设备指纹 + 邮箱 + 订单」三要素绑定的服务端
风控。

**密码学**：许可载荷改由服务端私钥 Ed25519 / ECDSA-P256 签名，客户端只内置公钥验签；**禁止用机器码
派生密钥**——机器码只能作为绑定标识参与签名；若保留 AES，须用服务端下发的一次性密钥 + HMAC 完整性
保护。移除「双存储一致性比对」，改用签名校验。

**客户端加固**：授权核心从「运行期 `Assembly.Load(byte[])` 明文程序集」改为原生 + 控制流平坦化，消除
「内存 dump 即得算法」这个单点；消除 `Days` 单字段驱动全部权益的写法，改为不可逆令牌 + 多因子校验；
本地许可被篡改时应触发服务端黑名单上报与功能降级，而不是仅本地覆写（本地覆写可被看门狗秒还原）。

**反回拨**：时间源改为服务端时间 + 单调计数器，避免只依赖本地 `DateTime.Now`。
