# 跨进程 52 点位与裸桩代理（项目B，v6.8.1）

> 案例类型：Windows x64 多进程商业套件 · 客户端授权流审计（CWE-602） · 代理 DLL 热补丁
> 脱敏：产品名、公司名、端点与样本哈希均已移除；点位表、RVA、补丁字节、日志状态与风险登记完整保留。

这个案例的难点不在任何单点，而在**形状**：授权判定被复制到四个进程里，
每一次构建都会重排地址，而更新程序又有能力把一切恢复原状。
把"改哪几个字节"当成答案，会在下一个版本上全部作废——上一代的 53 条点位在新版本上
**逐字节命中 0 条**，这就是最直白的证明。

---

## 一、目标画像

| 维度 | 判定 |
| :--- | :--- |
| 平台 | Windows x64，MSVC 编译 |
| 形态 | 四进程套件：UI 主程序 / 后台守护 / 远程推流服务 / 自动更新 |
| UI 框架 | Qt（判定结果同时以信号发射，不只是返回值） |
| 授权模型 | 服务端下发字段 + **客户端本地裁决**（CWE-602） |
| 地址稳定性 | 无（每次构建重排，跨编译单元位移不一致） |
| 交付形态 | 目标自身静态导入的系统 DLL 同名代理（`winhttp.dll`） |

四个进程的存在不是背景信息，而是工作量本身：Main 30 点、Service 18 点、RemoteService 4 点，
合计 **52 点**。只改 Main 会得到最典型的错误现象——界面看起来正常，几秒后徽标又回来了，
因为守护进程按自己的判定把状态推了回去。

## 二、为什么放弃"改名 + 双转发"

早期方案是经典的代理形态：把宿主自带的 `sentry.dll` 改名成 `sentry_orig.dll`，
再放一个同名的转发器，加载后转发到改名后的原件，并在 `DllMain` 里打补丁。
它能用，但代价明确：

| 代价 | 后果 |
| :--- | :--- |
| 需要两个额外文件 | 安装目录里多出 `*_orig.dll`，一眼可见 |
| 依赖加载顺序 | 任何改变加载时机的更新都可能失效 |
| 更新会重装模块 | 一次升级即静默回滚，用户看到"补丁自己没了" |
| 每个宿主各写一份转发 | 导出表庞大（169 项 / 17 项），维护成本高 |

演进后的方案换了思路：**不跟宿主抢模块名，而是挑一个宿主本来就静态导入的系统 DLL**。
四个主程序都静态导入 `winhttp.dll`，于是把这个同名文件放在程序目录即可：
不需要改名、不需要 `_orig`、单文件生效，连更新程序都会因为同样的原因自动加载它。

这一步的关键不是技巧，而是**先验证事实**：把四个 EXE 的导入表逐个查一遍，
确认所选模块在每一个里都存在。少一个，"单文件"这个故事就不成立。

## 三、裸桩：92 个 API 的零成本桥接

转发器最大的工程风险是签名。`winhttp.dll` 的导出里既有可变参数（variadic），
也有返回结构体（隐藏指针）的接口，用 C 写一层包装就要逐签名处理。

本案采用裸函数（naked）直接跳转：

```rust
#[unsafe(naked)]
unsafe extern "C" fn WinHttpOpen(/* … */) {
    naked_asm!("mov rax, [rip + WINHTTP_OPEN_SLOT]", "jmp rax")
}
```

三条收益：

1. **调用约定逐字保留**——不建栈帧、不动寄存器，可变参数与结构化返回都不会错；
2. **零开销**——一次 `jmp`，不是"包装 + 转发 + 返回"；
3. **单文件即插即用**——宿主的静态导入替我们完成了注入。

导出列表由原件导出表**生成**，不手写：一次生成 169 项转发，另一次 17 项。
手写列表的通病是"测试全过、现场崩在没想到的那个 API 上"。

## 四、52 点位表的形态

每条记录列：`host_exe, proxy_dll, id, section, file_off, rva, va, orig_len, patch_len,
orig_bytes, patch_bytes, semantic, verify`。

主程序节选：

| id | RVA | 原始 | 补丁 | 语义 |
| :--- | :--- | :--- | :--- | :--- |
| `nxmain_ad_gate_member_remove_ad_ok_bypass` | `0x12B9A3` | `0f 84 b9 01 00 00` | `90 90 90 90 90 90` | 条件跳转置 NOP，信号仍然发射 |
| `nxmain_skip_trial_banner_flow` | `0xCF01DF` | `0f 8e ed 00 00 00` | `e9 ee 00 00 00 90` | `jle` → `jmp`，跳过试用提示流 |
| `nxmain_resp_expiry_2099_12_31` | `0xD19C7A` | `e8 28 42 31 ff` | `b8 7f e6 85 f4` | 字段提取调用 → 立即数 `0xF485E67F`（2099-12-31 16:08 UTC） |
| `nxmain_resp_member_status_enabled` | `0xD19D0E` | `e8 8e 9f 2e ff` | `b8 01 00 00 00` | → `1` |
| `nxmain_resp_member_type_vip` | `0xD19D9A` | `e8 02 9f 2e ff` | `b8 01 00 00 00` | → `1` |
| `nxmain_resp_device_count_5` | `0xD19E25` | `e8 77 9e 2e ff` | `b8 05 00 00 00` | → `5` |
| `nxmain_resp_trial_status_used` | `0xD19FD4` | `e8 c8 9c 2e ff` | `b8 02 00 00 00` | → `2` |
| `nxmain_resp_privilege_enable` | `0xD1A2C6` | `e8 d6 99 2e ff` | `b8 01 00 00 00` | → `1` |
| `nxmain_parse_a_device_member_enabled` | `0x1086BBE` | `e8 de d0 f7 fe` | `b8 01 00 00 00` | 解析路径 → `1` |
| `nxmain_ui_member_check_direct` | `0xB50D80` | 22 字节站点 | 改 3 字节 | UI 判定，局部覆写 |

两种形态反复出现：

- **分支中和**：`jcc` → `nop…` 或 `jmp`。保住信号发射，UI 才会真的更新。
- **调用 → 立即数**：把"提取字段"的 `call` 换成 `mov eax, imm32`，字段值恒定。

第二种只在被调用函数返回纯标量时成立。返回聚合体或字节集的函数这样改，
会在调用点解引用一个非指针值——崩溃点离改动点很远，极难归因。

## 五、四态日志：让"没生效"可被区分

| 状态 | 含义 | 为什么必须独立 |
| :--- | :--- | :--- |
| `APPLIED` | 比对一致并写入 | 唯一成功态 |
| `ALREADY` | 目标字节已等于补丁 | 同进程二次加载，不是错误 |
| `OUTOFRANGE` | RVA 不在本镜像内 | 加载了代理但不是目标宿主 |
| `MISMATCH` | 与期望字节不符 | 版本漂移；**一个字都不写** |
| `SKIPPED` | 明确声明不覆盖该宿主 | 如 `host 'powershell.exe' not covered -> no modification` |

四态的价值在于**可归因**：只写"done"的日志，遇到"没生效"时无法区分
"补丁失败""补丁重复执行""这个宿主本来就不该改"。

`MISMATCH` 是最重要的一条：它把"版本升级导致偏移失效"这个致命风险（R1）
降级为一条日志——因为代理是**先比对、再写入**，不匹配就跳过。

## 六、跨版本漂移：什么能平移，什么不能

| 模块 | 跨构建行为 | 结论 |
| :--- | :--- | :--- |
| `NxMain.exe` | 分区位移恒定：`+0xcf00` / `+0xadc0` / `+0x1320` / `+0x9530` | 同一编译单元内的地址可按固定差值平移 |
| `NxService.exe` | 位移**不恒定** | 平移会得到"看似合理但其实错位"的地址，禁止 |
| `RemoteService.exe` | 体量增长约 3.66 倍 | 完全不可平移，必须从头重新定位 |

平移在 Main 上之所以成立，是同编译单元内相邻字段的间距得到验证：
账号缓存通道整体 `+0xcf00`，相邻字段间距 `+0x101 / +0xf1 / +0x1f0` **100% 吻合**。
这条验证不是形式主义——没有它，"平移"只是一次运气。

位移不可用的地方，改用**构建无关签名**：

- **五元调用间距指纹**（Service）：连续五次 `call` 之间的相对距离
  `+0x15a / +0x63 / +0xc2 / +0x77` 与 `+0x88 / +0x53 / +0x1a1 / +0xe7`；
- **结构体字段偏移签名**：`0x2c8 / 0x2d4 / 0x2d8 / 0x300 / 0x308` 与
  `0x378 / 0x384 / 0x388 / 0x3b0 / 0x3b4` 在权益字段访问处反复出现；
- **字符串锚点**：`member_remove_ad_ok`、`device_member_status`、`member_trail_status`、
  `v1/member/trial`，以及推流辅助程序的 UTF-16 名称。

上一代 53 条语义点位在新版本上 **0/53 逐字节命中**；点位总数从 61 收敛到 52
（重标定 45、合并 5→6、改法升级 1、等价替换 2、新增 2、删除 4）。
这两组数字合起来说明一件事：**补丁表是对某一镜像的事实陈述，不是可移植资产。**

## 七、部署与写入范围

写入：

- `nx_main\sentry.dll` → 改名 `sentry_orig.dll`（仅旧布局）
- `nx_main\version.dll`、`nx_main\version_orig.dll`（仅旧布局）
- `nx_main\winhttp.dll`（当前布局：唯一新增文件）
- `nx_main\nx_guard_*.log`
- `backup_proxy_guard\<时间戳>\`（被替换文件的备份）

**未写入**：三个 EXE 本体、注册表、系统目录、服务配置。
回滚脚本 `deploy\Restore-ProxyDll.ps1`，且必须**在实验环境里真的跑一次**——
没跑过的回滚只能叫希望。

部署后核对：`certutil -hashfile` 三个 EXE 未变、`Get-AuthenticodeSignature` 为 `Valid`、
UI 启动后日志报出该宿主应有的点位数（UI `points=30`、守护 `points=18`）。

## 八、五场景验证清单

| 场景 | 观察点 |
| :--- | :--- |
| 1 启动 | 无开屏广告、无侧栏推广；无试用 Banner；头像显示会员；到期日 2099-12-31；日志 `points=30` |
| 2 登录 | 登录后不回退为普通用户；设备数 ≥5；5 秒内不闪回；守护进程日志 `points=18` |
| 3 刷新 | 反复刷新 3 次，会员态与到期日稳定；`configs\main\nx_main.json` 持久 `member_status=1` |
| 4 退出登录 | 状态清理正确，不残留伪会员态 |
| 5 重启 | 冷启动后仍为会员态（证明不是仅进程内有效） |

场景 2 的"5 秒内不闪回"是专门为多进程形态设的：如果只改了 UI，闪回几乎必然发生，
而"肉眼看起来成功"的时刻恰好在那 5 秒之内。

## 九、风险登记（R1–R9）

| 编号 | 风险 | 缓解 |
| :--- | :--- | :--- |
| R1 | 版本升级导致点位失效 | 先比对再写；`MISMATCH` 零写入 |
| R2 | 官方完整性自校验 | 本版本未发现；不假设永远没有 |
| R3 | 服务端权威未被攻破 | 本案例没有触达服务端真值，报告中必须写明 |
| R4 | 可选点位置信度低 | 开关 `GUARD_DISABLE_OPTIONAL=1` 可关掉 2 点 |
| R5 | RemoteService ①a 置信度中等 | 默认集不纳入，直到能稳定复现 |
| R6 | 到期时间常量 `0xF485E67F` 可能与毫秒级 UI 不符 | 验证渲染出来的日期，而不是只看常量 |
| R7 | 代理被非目标宿主加载 | 走 `SKIPPED` 分支，不写内存 |
| R8 | 常驻服务未重启，仍是旧镜像 | 部署后重启服务并复查日志 |
| R9 | 杀软对同名系统 DLL 报毒 | 预期内；记录，不要靠改名"绕过" |

R3 是这份材料里最需要保留的一条：52 个点位证明了**客户端可被改写**，
没有证明**服务端可被绕过**。任何把这两件事混为一谈的报告都是失实的。

## 十、限制与未验证项

| 项 | 状态 |
| :--- | :--- |
| 是否存在未发现的判定点 | `[unverified]` 52 点是"已找到"的集合，懒加载代码未穷举 |
| 五元调用间距指纹的普适性 | `[inferred]` 仅在两个构建上验证 |
| 服务端权威的实际强度 | `[unverified]` 未做服务端测试 |
| 更新通道阻断的副作用 | `[inferred]` 静默破坏更新有独立风险，报告中单列 |
| 合成宿主工装对真实宿主的代表性 | `[observed]` 字节级验证通过，行为级仍需真实安装复核 |
