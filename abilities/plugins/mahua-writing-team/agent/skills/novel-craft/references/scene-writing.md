# 场景写作

一章不是一个整体，是若干场景串起来的。写崩的章节通常不是「句子不好」，是**场景缺一个环节**。

## 一、场景的定义

**同一时间、同一地点，发生的一个戏剧性事件。**

四问缺一不可：

1. 发生了什么事？
2. 谁想得到什么？
3. 谁在阻碍？
4. 结局是什么（通常是某人被迫做出新决定）？

第 4 问答不出来，这个场景就只是「信息段落」，应当在 `mahua_plan_chapter` 的阶段合并或删掉。

## 二、七种场景类型

| 类型 | 驱动力 | 常见失误 |
| --- | --- | --- |
| 对话 | 信息交换下的控制权争夺 | 双方只交换信息，没有一方想改变另一方 |
| 行动 | 目标 vs 障碍的物理对抗 | 障碍太弱，主角一次就过 |
| 内省 | 人物对已知事实的重新解释 | 复述读者已经知道的事 |
| 揭示 | 新事实改变既有理解 | 揭示的东西读者早就猜到了 |
| 关系 | 两个人的距离发生变化 | 变化没有代价 |
| 氛围 | 让读者感到某种压迫或辽阔 | 只有景，没有人 |
| 过渡 | 压缩时间与空间 | 写成流水账 |

一章里至少要有两个**不同类型**的场景。全是对话场景会飘，全是内省场景会闷。

## 三、对话的三层潜台词

表面层：两人在谈 X。
第二层：其中一人在试图控制另一人。
第三层：两人都在掩饰对彼此的真实感受。

写作时问自己：**这句台词如果只是字面意思，为什么需要这个人现在说？**

## 四、场景的入口与出口

- **入口晚一点**：从冲突已经开始的那一刻写起，不写「他推门进来，寒暄，坐下」。
- **出口早一点**：在决定做出之后立刻切走，不等后果铺开——后果留给下一个场景。

## 五、与本插件工具的配合

1. `mahua_plan_chapter` 写 goal / conflict / hook 时，顺带列出本章的 2–4 个场景及其类型；
2. `mahua_context` 给出的 `relatedChapters` 若有同类型场景，回读一次找节奏（`mahua_read_chapter`）；
3. 写完用 `mahua_style_stats` 看对话占比：低于 20% 说明叙述压过场景，高于 60% 要检查是否缺环境锚点；
4. `mahua_check_consistency` 只能查事实冲突，场景层面的「没有阻碍」要自己看出来。
