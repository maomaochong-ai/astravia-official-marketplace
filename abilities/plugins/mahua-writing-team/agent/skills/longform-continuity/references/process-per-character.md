# 角色即子进程

长篇里「人物走形」不是笔力问题，是**没有给角色一份可持续的状态**。这一篇把每个主要角色当成一个
有独立状态的进程来维护：它有自己的记忆、目标、关系，和上次退出时的位置。

## 一、状态卡的六个字段

每个主要角色一张卡，随章更新：

```
欲望   —— 这卷里他最想要的一件事（可被拒绝）
恐惧   —— 最怕失去的东西（可被夺走）
立场   —— 对主角：盟友 / 对手 / 摇摆（会变，变了要记账）
账本   —— 他欠谁、谁欠他（信用是长期冲突的燃料）
已知   —— 他知道哪些事实（读者的信息差由此产生）
位置   —— 最近一次出场在哪里、和谁在一起
```

「已知」这一项最常被漏。读者知道、角色不知道，才是悬念；角色知道而读者不知道，是惊奇。
两者都要求你明确写出**谁知道什么**。

## 二、出场即变化

一个角色出场，要么改变目标，要么改变关系，要么改变信息。三者都不改变的出场是客串，删掉。

检查：本章结束时，把每个出场角色的状态卡与上一章对比，**至少两个字段变了**。

## 三、关系是双向的

不要写「A 信任 B」，写「A 信任 B，B 在利用这份信任」。单向关系在长篇里会僵化，
因为只有一边能变。

关系的四种变化：靠拢（信任/亲密↑）、疏远（↓）、反转（盟友↔对手）、错位（一方变了另一方没变）。
第四种最好用：它不需要事件，只靠时间。

## 四、退场与回收

角色退场（死亡、离开、消失）之前必须做完三件事：

1. 他欠的账结清或明确挂账；
2. 他的「已知」转移到别人身上，或随他消失并留下后果；
3. 他的欲望有一个结局（实现 / 破灭 / 移交）。

没做完就退场，读者会觉得这个人白写了。

## 五、和本插件工具的配合

- `mahua_save_foundation` 的 `cast` 是出场白名单：`mahua_check_consistency` 会把不在 `cast` 里的名字报成
  `chapter.unknownCharacter`。新增角色先加 `cast`，再写进正文。
- `mahua_attach_chapter_facts` 记录每章谁出场（`facts.characters`）。这是「位置」与「出场频率」的来源，
  也是 `mahua_context` 相关章节推荐的第一条判据。
- 章纲里的 `mahua_plan_chapter` 不必写状态卡全文，但要在 `conflict` 里写出**这一章谁的目标被谁挡住**。
- 弧结束时 `mahua_save_arc_summary` 写清「哪些角色的状态卡变了」，这是弧有没有推进的硬证据。
