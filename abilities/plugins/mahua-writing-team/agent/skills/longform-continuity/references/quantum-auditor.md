# 审计式复读

「量子审计」这个名字来自 novel-master，机制其实很朴素：**同一段文字，用一组固定的问题复读一遍**，
每次只问一件事，不要一边读一边改。

## 一、为什么需要它

写完一章的当下，作者记得自己「想写什么」，所以读的时候会自动补全没写出来的部分。
隔一段时间再读，或者按固定问题读，才会发现缺口。审计的目的是**制造视角差**，不是挑毛病。

## 二、六个审计问题（按顺序，一次只答一个）

| # | 问题 | 不合格的样子 |
| --- | --- | --- |
| 1 | 这一章谁想要什么？ | 答不出一个具体的人 + 一件具体的事 |
| 2 | 谁在阻止？ | 只有「命运」「环境」这类非人格障碍 |
| 3 | 哪一句是本章的转折？ | 找不到一句能指认的句子 |
| 4 | 读者在这一章结束时会想问什么？ | 什么都不想问 |
| 5 | 有没有一句话可以删掉而不影响任何东西？ | 有，且有五句以上 |
| 6 | 如果把这一章放到别的书里，会不会显得突兀？ | 不会——说明没有这本书特有的东西 |

第 3 题和第 6 题最有效。第 6 题答「不会突兀」是严重信号：这一章缺少本作独有的设定、人物或语气。

## 三、证据式评审

`mahua_save_review` 的七个维度，每一维都必须**引用原文**才能给分：

| 维度 | 举证要求 |
| --- | --- |
| plot | 指出本章的不可逆事件在第几段 |
| character | 引用一句只能出自这个角色的台词 |
| pacing | 指出哪些段落是快、哪些是慢，给出理由 |
| prose | 引用一处具体的好句子与一处坏句子 |
| dialogue | 引用一处潜台词（字面与真实意图不同） |
| continuity | 指出与前面哪一章的哪个事实接得上 |
| hook | 引用本章最后一句，并说明它打开了什么 |

没有引用就不给分。这是「量子审计」在本插件里的落地方式：**评分是证据的函数，不是印象的函数**。

## 四、审计不该做的事

- 不在审计的同时改稿：改稿会打断视角差，先把六个问题答完。
- 不因为一处不好就否定整章：先判断它是「局部句子」还是「结构缺口」。
- 不给「还行」这种分数：七维要么有举证，要么按不合格处理，中间态没有意义。

## 五、与工具的顺序

```
mahua_read_chapter      → 读全文（不是读摘要）
mahua_check_consistency → 事实层先过一遍，避免引用了错误事实
mahua_style_stats       → 句长/对话占比/重复短语给了量化底
mahua_check_rules       → 禁用词与人称
mahua_save_review       → 七维 + mustFix
```

`mustFix` 是硬门：不为空时章节不会被判为 reviewed，指针不会前进。写 `mustFix` 时写**可执行的修改动作**，
不要写「节奏偏慢」这类判断。
